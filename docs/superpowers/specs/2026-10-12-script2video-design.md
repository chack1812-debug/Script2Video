# Script2Video 設計書

日付: 2026-10-12 / 状態: 承認済み(2026-10-13) / 台本の書式は [台本仕様.md](../../../台本仕様.md)

## 1. 目的

Script2Voice-Rust版から音声合成を外し、**収録した肉声**を起点に、台本から完成動画までを作るパイプラインを新規プロジェクトとして作る。

流れ: 台本 → 採番 → (収録) → 音声連結・計時・音響効果 → 情景から指示書を生成(AI) → 挿絵・動画クリップの生成 → 台詞の吹き出しの重ね合わせ(ブラウザGUI) → 最終合成(1本の動画)。

## 2. 分解

独立した4つのサブプロジェクトに分け、それぞれ spec → 計画 → 実装のサイクルを回す。

| # | サブプロジェクト | 工程 | 本書の扱い |
|---|---|---|---|
| ① | 台本+音声パイプライン (`number` / `build`) | 採番、音声連結、無音削除、計時、音響効果、`timeline.json` | **詳細設計** |
| ② | 指示書生成 | 情景・人物像から画像/動画生成AIへの指示書を作る。AIが素材を直接生成・取得する場合の受け渡し | 契約のみ(§7) |
| ③ | 吹き出し調整(ブラウザGUI) | 素材に台詞の吹き出しを重ね、位置・表示時間を調整 | 方式のみ(§8) |
| ④ | 最終合成 | 音声+挿絵+動画クリップ+吹き出しを1本の動画にする | 契約のみ(§9) |

サブプロジェクト間の契約は、①が出力する `timeline.json`(§6)、③が出力する `bubbles.json`、②/④が使う素材フォルダである。

## 3. 前提と決定事項

- 実装言語は **Rust**。Script2Voice-Rust版(`D:\UDS\宇摩コードワークス\Script2Voice-Rust版`)のクレートをコピーして改造する。リポジトリは `D:\UDS\宇摩コードワークス\Script2Video`、Script2Voice は現状維持とする。
- 音声合成エンジン(`s2v-engines`)は持たない。
- 画像・動画の生成そのものは外部ツールで行う。Higgsfield のように AI から操作できるツールでは、AI(Claude Code 等)が生成・取得を直接行う場合がある。本体は生成を行わず、指示書の元データ、素材の置き場所、命名規約を提供する。
- 台本のシーン番号は `#paragraph`(カット)単位、台詞番号は台本全体で一意(台本仕様 §1)。

## 4. リポジトリ構成

Cargo ワークスペース。

| クレート | 由来 | 役割 |
|---|---|---|
| `s2v-core` | Rust版を改造 | 台本パーサ、採番、タイムライン、型。エンジン関連を除去 |
| `s2v-audio` | Rust版を流用 | リサンプル、定位、残響。無音削除、入力の変換、ラウドネス正規化を追加(ピーク正規化と台詞ごとのリミッタは廃止) |
| `s2v-export` | Rust版を流用 | SRT、FCPXML、`timeline.json`、台本HTML |
| `s2v-video` | Rust版を流用 | ffmpeg による合成(④) |
| `s2v-bubbles` | 新規 | ブラウザGUI用のローカルサーバ(③) |
| `s2v-cli` | Rust版 `src/main.rs` を改造 | コマンド `number` / `build` / `bubbles` / `compose` |

流用元の移植は、元のコミットを記録した上でコピーし、元のテストも一緒に移す。以後は独立して進化させる。

## 5. ①の詳細設計

### 5.0 実装の段階(①a / ①b / ①c)

①の仕様は先に確定させるが、実装は段階に分ける。前の段階が完了してから次へ進む。

| 段階 | 範囲 | 該当する節 |
|---|---|---|
| **①a** | 単独ファイル(1台詞1ファイル `S01_L003.wav`)、`number`、入力の変換(モノラル確認・48kHz)、ラウドネス正規化、無音削除、`overlap`/`at`、SE/BGM、`timeline.json`/SRT/FCPXML/トラック別 wav | §5.1〜§5.8(テイク以外)、§5.10、§5.11、§6、§10 の「①a の対象」表 |
| ①b | 混合トラックのテイク(連続収録)。無音による自動分割、`.cuts`、テイク内の配置 | §5.9、台本仕様 §3.2〜§3.4(混合)、§10 の項目 2a〜2d(混合) |
| ①c | 役別トラックのテイク(同時収録)。同期の検査、漏れ込み、重なりの再現 | 同上(役別) |

- ①a は範囲ファイル名(`S01_L003-L007.wav` など)を「未対応の形式」として**照合の対象から外し**、警告だけを出す(終了コード 1)。`takes[]` にも記録しない。その範囲の台詞は、単独ファイルがあればそれを使い、無ければ `no_file` で不足にする。
- **単独ファイルの専用経路**: 単独ファイル(`S01_L003.wav`/`.flac`)は、①b 以降も §5.9 を通さない。発声検出(`take_gate_db`)・`.cuts`・順序検査は行わず、§5.3 の無音削除(`trim_threshold_db`)だけで使用範囲を決める。使用範囲は、最初に音が現れる位置の `trim_head_margin_ms` 手前から、最後に音がある位置の `trim_tail_margin_ms` 後まで。段階を進めても、単独ファイルの結果が変わらないようにするため(たとえば全体が -45 dBFS の単独ファイルは、`take_gate_db` -40 dBFS では検出されないが、-50 dBFS の無音削除では使える)。
- `timeline.json` の `takes[]`、`take`/`track`、`src_start_ms`/`src_end_ms` は ①a から出力する(単独の台詞は、範囲が1台詞のテイクで `track` は null)。①b・①c で追加しても契約が変わらないようにするため。
- 以下の節で「テイク」を述べる箇所は、①a では単独の台詞に読み替える(`takes[]` には、台詞ごとに台詞 ID と同名のテイクを記録する。§6)。

### 5.1 `number`
台本仕様 §4 のとおり。台本に ID を書き込み、`台本名.html`(印刷・閲覧用)を出力する。

`台本名.html` の内容: タイトル、登場人物(役名・話者名・外見描写)、シーンごとの見出し(番号・名称・情景)、台詞の表(台詞ID・役名・台詞)。印刷向けスタイルを `@media print` で用意し、ブラウザの印刷で紙・PDFにできる。

### 5.2 `build`: 処理の順序

1. **パース**。台本を読み、役・シーン・台詞・コマンドの列を得る。
2. **照合**。`--voice-dir` の収録ファイルを、ファイル名から**テイク**(台詞の範囲+トラック)に解釈し、台詞に対応付ける(台本仕様 §3)。不足・重複・形式エラーを集める。同期の検査は、取り込み後(手順3)に行う。
3. **取り込み**。テイクごとに全トラックを読み込み、モノラルであることを確認して 48kHz へ変換し、中間ファイルに書く(§5.10)。レベルは変えない。役別トラックの長さの検査(同期の検査。①c)は、変換後のここで行う(§5.9 手順2)。
4. **切り分けと無音削除**。取り込み後の音声で、単独ファイルは無音削除(§5.3)だけで使用範囲を決める。テイク(①b・①c)は台詞に切り分け(§5.9)、テイクの端の無音を削除する(§5.3)。
5. **ラウドネス正規化**。台詞ごとに、同じ目標ラウドネスへ正規化する(§5.10)。
6. **配置**。台詞の開始時刻を決める(§5.5)。
7. **音響処理**。台詞ごとに定位・距離・残響を適用する(既存のDSPの順序をそのまま使う。ただし、ピーク正規化と台詞ごとのリミッタは行わない。§5.10)。
8. **ミックス**。台詞・BGM・SE をそれぞれ別トラックに加算し、`full_dialogue.wav` に合成する(§5.4)。
9. **出力**。`timeline.json`、SRT、FCPXML、トラック別wav、`Process.log`、`work/`。

### 5.3 収録音声の前後の無音削除

無音削除は**テイク(§5.9)の先頭と末尾だけ**に適用する。台詞ごと・トラックごとの削除は行わない(トラック間の同期と、テイク内の間を保つため)。単独の台詞は範囲が1台詞のテイクなので、従来どおり台詞の前後が削除される。

- 検出は、取り込み後でレベルを変えていない音声(§5.10)に対して、10ms 窓の RMS で行う(窓・丸めの規則は §5.11)。しきい値は既定 -50 dBFS(`config.toml` の `trim_threshold_db`)。役別トラックでは、全トラックのうち**最も早く音が現れる位置**と**最も遅く音が消える位置**を共通の端として、全トラックに同じ位置を使う。
- 先頭は最初に音が現れる位置の `trim_head_margin_ms`(既定 30ms)手前、末尾は最後に音がある位置の `trim_tail_margin_ms`(既定 80ms)後までを残す。語頭の子音・語尾の余韻の欠けを避ける。
- フェードは、台詞の正規化工程(§5.10 B)で一度だけ掛ける。この節では掛けない。
- **元の収録ファイルは変更しない**。削除はメモリ上で行う。
- `.cuts` を使うテイクには、共通の端の決定とトリムを行わない。`.cuts` の指定範囲がそのまま使用範囲で、`takes[].trims` には、`head_ms = 指定範囲の最小開始`、`tail_ms = トラックの長さ − 指定範囲の最大終了` を記録する(指定区間どうしの間の未使用部分は含めない)。
- 台詞のある役のトラックが全区間しきい値以下なら、そのテイクは「無音ファイル」として不足扱いにする(§5.6)。`.cuts` のテイクでは、**各台詞の指定範囲の内側**がすべてしきい値以下の場合に、同じく `silent` で不足にする(指定範囲の外側は検査しない)。
- 削除した量は `timeline.json` の `takes[].trims`(トラックごとの頭・末尾の削除量)に残す。役別トラックの長さが許容差内で異なっても、共通の終了位置との差をトラックごとに記録する。台詞ごとの録音上の位置は `lines[].src_start_ms` / `src_end_ms` に残す(§6)。
- 長さの計測と開始時刻の計算は、削除後の長さを基準にする。
- 内部の無音(台詞の途中の間、テイク内の台詞間の間)は削除しない。
- テイクの切り分けの発声検出には、別設定 `take_split_min_gap_ms`(既定 200ms)と `take_gate_db`(既定 -40 dBFS。役別トラックの漏れ込み対策で、`trim_threshold_db` より高い)を使う。`take_gate_db` は検出専用で、音声から漏れ込みを除去しない(台本仕様 §3.2)。
- 役別トラックの長さの許容差は `sync_tolerance_ms`(既定 10ms)。短いトラックは末尾を無音で補い、最も長いトラックの長さに揃えてから処理する(長い側の語尾を落とさないため)。共通の終了位置は、補った後の長さを上限とする。`trims` の `tail_ms` は、各トラックの元の長さではなく、揃えた後の長さと共通の終了位置との差で記録する。

### 5.4 トラックとミックス

| トラック | 内容 |
|---|---|
| dialogue | 台詞(重なりは加算) |
| bgm | `#bgm_start` / `#bgm_stop` |
| se | `#se`(台詞にかぶせた配置を含む) |

`full_dialogue.wav` は3トラックの合成。トラック別 wav も同時に出力し、動画編集ソフトで別トラックに載せられるようにする。加算時のクリップは、トラックごとの音量補正とマスターのソフトリミッタで防ぐ。台詞は台詞ごとのリミッタを持たないので(§5.10)、台詞のピークの処理はマスターのソフトリミッタだけが行う。

- **書き出し形式**: `tracks/*.wav` はマスター前の 32bit 浮動小数(クリップしない)。`full_dialogue.wav` はマスターのソフトリミッタ(ステレオ連動、上限 `[mix] master_ceiling_db`、既定 -1.0 dBFS)を通した 24bit 整数。
- `tracks/*.wav` を編集ソフトで足し合わせた結果は、非線形のマスター処理を通さないため、`full_dialogue.wav` と同一にはならない(編集ソフト側で最終の音量調整を行う前提)。

### 5.5 台詞の配置

2つの時刻を区別する。
- `last_line_end`: 台本の並びで直前の台詞の終了時刻(配置後)。
- `cursor`: ここまでに置いた全台詞の終了時刻の最大値(後退しない)。

- 通常の台詞は `cursor + 無音` で開始する。無音は、話者が同じなら `@pause sentence`、交替なら `@pause cast`、シーンの先頭なら `@pause paragraph` とする(Script2Voice と同じ)。
- `overlap=N` の台詞は `last_line_end - N` で開始し、無音は入れない。`last_line_end - N < 0` なら警告して 0 に丸める(終了コード 1)。
- `at=台詞ID+N` の台詞は、参照した台詞の開始時刻+N で開始する。参照先が不足していた場合、仮の無音の長さを基準にする(§5.6)。
- 台詞を置いたあと、`cursor` は `max(それまでの cursor, その台詞の終了時刻)` に更新する(後退しない)。
- `#pause N` は `cursor` を N ms進める。
- **テイク**(台本仕様 §3.3)は、台本上で先頭の台詞(アンカー)を上の規則で置く(`overlap=`/`at=` はアンカーにだけ効く)。時刻 P に置かれたとき、ほかの台詞の開始は `P + (その台詞の src_start_ms − アンカーの src_start_ms)` とする。順序検査(§5.9)によりこの差は 0 以上なので、配置時刻が P より前になることはない。テイク内の台詞に `@pause` は挿入せず、テイク内の台詞同士の重なり(役別トラック)も録音どおり保たれる。
- **テイク内のコマンド**: `#pause` と `#bgm_start`/`#bgm_stop` は警告して無視する。`#se` は、`at=`/`end=` があればそれに従い、無ければ台本の並びで直前の台詞の終了時刻に置く。`#paragraph` のシーン開始は、配置の完了後に、そのシーンに属する全台詞の開始時刻の最小値として確定する(テイク内の最初の台詞とは限らない)。素材の切り替えと順序検査は、確定した値を使う。
- **シーンの順序**: 確定したシーン開始時刻が、台本の並びで後ろのシーンのほうが前のシーンより早くなったら、エラー(終了コード 2)にする。同じ時刻に始まるのは許す(単調非減少)。
- **無言のシーン**(台本仕様 §2.8): 台詞を含まず `#pause` を含むシーンは、`start_ms` をシーンの始まりの時点の `cursor`、`end_ms` を `start_ms + シーン内の #pause の合計` とし、`cursor` を `end_ms` に進める。`@pause paragraph` は加えない。台詞も `#pause` もない、または `#pause` の合計が 0 のシーンは、エラー(終了コード 2)にする。
- 無言のシーンも、シーン開始時刻の順序検査(上記)の対象にする。

### 5.6 不足した収録の扱い(処理は継続)

- **失敗の単位はテイク全体**。切り分けの失敗、`.cuts` の不備、順序検査の不一致、ファイルの破損・非モノラル・読めない形式(`bad_format`)、無音、ラウドネスの測定不能(`unmeasurable`)、役別トラックの長さの不一致、同じ台詞を覆う複数のファイル、のどれかで、そのテイクの全台詞が不足になる。エラーメッセージを `Process.log` と標準エラーに出す。処理は止めない。
- 複数のテイクが同じ台詞を覆う(重複)ときの配置は、台本の並びで先頭の台詞を持つテイク(同じなら ID の辞書順)の所属で判定する。`lines[].take` の記録と同じ規則。
- 不足の台詞は、通常の台詞と同じ規則で順番に配置し、仮の長さの無音で埋める。仮の長さは、台詞の文字数×`placeholder_ms_per_char`(既定 200ms)。テイクの録音位置は使わない(仮の無音が次の台詞に食い込まないため)。正常なテイクと同じく、最初の台詞以外の `overlap=`/`at=`/`#数字` とテイク内の `#pause`・`#bgm_*` は無視する(`#se` は§5.5)。
- `timeline.json` では `missing: true` と `reason`(§6)を付ける。字幕は出力する。
- 終了コード: 0=全件OK、1=警告・不足あり(出力は完成)、2=台本の構文エラー等(出力なし)。

### 5.7 エラー処理まとめ

| 事象 | 処理 | 終了コード |
|---|---|---|
| 収録ファイル不足/形式エラー/無音 | そのテイクを不足扱い(仮の無音)で継続 | 1 |
| 同じ台詞を覆うファイルが複数(単独とテイクの併存、混合と役別の併存など) | 関係するすべてのテイクを不足扱いで継続。ファイル名を列挙 | 1 |
| 発声区間が足りず切り分けできない | そのテイク全体を不足扱いで継続。`.cuts` を促す | 1 |
| `.cuts` の不備(台詞の欠落・重複、別の役の ID、開始≧終了、範囲外、区間の重なり、順序違い、書式エラー) | そのテイク全体を不足扱いで継続 | 1 |
| 役別トラックの長さの差が(48kHz 変換後に)`sync_tolerance_ms` を超える | そのテイク全体を不足扱いで継続 | 1 |
| 収録ファイルがモノラルでない、非有限値(NaN/Inf)を含む、読めない形式 | そのテイクを不足扱い(`bad_format`)で継続 | 1 |
| ラウドネスを測定できない(§5.10 B) | そのテイクを不足扱い(`unmeasurable`)で継続 | 1 |
| 正規化のゲインが上限・下限に掛かった | 警告して継続(適用ゲインは制限後の値) | 1 |
| `cache.json` の破損、`work/` の出力ファイルの欠損・不一致 | 警告なしで再生成して継続(ログに記録) | 変えない |
| `[normalize]`/`[mix]` の設定値が範囲外 | エラー。出力しない | 2 |
| `work/` に書き込めない | エラー。出力しない | 2 |
| 切れ目の判定が曖昧 | 警告して継続 | 1 |
| 切り分け後の順序(録音上の開始位置)が台本と不一致 | そのテイク全体を不足扱いで継続 | 1 |
| テイク内の最初の台詞以外に `overlap=`/`at=`/`#数字`、テイク内の `#pause`・`#bgm_*` | 警告して無視(構文エラー等の検査が先) | 1 |
| 範囲の始点が終点より後ろ、または ID が存在しないファイル名 | 警告して無視 | 1 |
| ①a で、範囲を示すファイル名(`-` を含む) | 警告して照合の対象から外す(その範囲の台詞は、単独ファイルがあればそれを使い、無ければ `no_file`) | 1 |
| 台本にない台詞IDを含むファイル | 警告して無視 | 1 |
| 範囲内に台詞が無い役のトラックのファイル | 警告して無視 | 1 |
| BGM/SE ファイルが見つからない | その命令を無視して継続 | 1 |
| ID重複、`at` が未来参照、`overlap` と `at` の併用、未定義の役名、台本の並びで後ろのシーンの開始が前のシーンより早い、台詞も `#pause` も含まない(または `#pause` の合計が 0 の)シーン | エラー。出力しない | 2 |

### 5.9 テイクの切り分け

この節は ①b・①c で実装する。**単独ファイルは、この節を通らない**(§5.0)。ただし `timeline.json` への記録は、単独の台詞を範囲が1台詞のテイクとして扱う形式にそろえる(§6)。切り分けの仕様の正本は台本仕様 §3.2。ここには実装の手順を書く。

1. **解釈**: ファイル名を `<台詞範囲>[.<役名>].<拡張子>` に分解し、範囲を台本上の位置(並び)で台詞列に展開する。役名が付くものは役別トラック。テイク ID は範囲の部分(例 `S01_L003-L007`)。同じ範囲の混合と役別が併存すると、1つのテイクとして `duplicate` で不足にする。同じ台詞を覆う別の範囲のファイルがあれば、関係するテイクを不足にする(§5.6)。
2. **同期の検査**: 役別トラックは、48kHz へ変換した後の長さの差が `sync_tolerance_ms` 以内であることを確認する(入力のサンプルレートは問わない)。短いトラックは末尾を無音で補う(§5.3)。開始位置の一致は検証できない(収録側が保証する)。
3. **区間の抽出**: トラックごとに `take_gate_db` 以下が `take_split_min_gap_ms` 以上続く無音区間を求め、発声区間を得る。トラックの先頭・末尾の無音は切れ目の候補から除く。台詞のある役のトラックで発声区間が1つも得られなければ、そのテイク全体を `silent` で不足にする(`take_gate_db` を下回る小さな声も含む)。
4. **切れ目**: 混合は台詞数 K で内部無音の長い順(同じ長さなら録音上で早いもの)に K-1 個を選び、中点を切れ目にして K 個のまとまりを作る。役別はトラックごとに、その役の台詞数で同じことをする。選べる内部無音が K-1 個に満たなければ、そのテイク全体を不足にする。
5. **曖昧判定**: 選んだ内部無音と選ばれなかった内部無音がどちらも1つ以上あるとき、選んだものの最短 ÷ 選ばれなかったものの最長 が 1.3 未満(同じ長さを含む)なら警告する。K=1 や、候補がちょうど K-1 個のときは判定しない。
6. **`.cuts`**: テイクのすべてのトラックに `.cuts` があるか、1つも無いかのどちらか(混在は `cuts_invalid` で不足)。`.cuts` があれば手順3〜5と手順7を行わない(手順8の順序検査は行う)。検証(台本仕様 §3.2)に通れば、`.cuts` の開始・終了をそのまま `src_start_ms`/`src_end_ms` とする。検証に失敗したらテイク全体を不足にする。
7. **台詞の区間**(`.cuts` がないとき): 手順4のまとまりごとに、まとまりの最初の発声の開始から最後の発声の終了までを求める。端は `trim_threshold_db` で音が残っている位置まで広げ(隣の台詞との無音の中点が上限)、`trim_head_margin_ms`/`trim_tail_margin_ms` を付けて `src_start_ms`/`src_end_ms` とする。マージンを付けた後も、隣の台詞との間の中点とファイルの端を超えない。同じトラック内で台詞の範囲は重ならない。§5.3 の共通の端は、テイク全体の使用範囲の外枠(これより外側は使わない)で、各台詞の端とは別。台本上で最後の台詞の終了も、ほかの台詞と同じくこの手順で決め、共通の端まで延ばさない。共通の端を超える範囲は、共通の端で切る。
8. **順序検査**: 全台詞を `src_start_ms` で並べ、台本の順序と一致するか確認する(同じ開始位置は一致とみなす)。`.cuts` にも適用する。不一致ならテイク全体を不足にする。
9. **正規化と音響処理**: ここでは行わない。切り分けた台詞の範囲(`src_start_ms`/`src_end_ms`)を後続へ渡すだけで、ラウドネス正規化(§5.2の5、§5.10)と音響処理(§5.2の7)は、§5.2 の順序で行う。
10. **切り分けの記録**: 毎回 `Process.log` に、各台詞の `src_start_ms`/`src_end_ms` を一覧で出す。自動検出のテイクには、選んだ切れ目と選ばれなかった候補の無音の長さも出す。`.cuts` のテイクには、指定範囲と検証結果を出す。人間が誤分割を確認するため(自動切り分けの保証範囲は台本仕様 §3.2)。
11. **混合トラックの限界**: 1本に全役が入っているため、同時発声は切り分けられない。重なりが必要な台本は、役別トラックで収録するか、単独で収録して `overlap=` を使う。

### 5.10 入力の変換とラウドネス正規化

台詞・役・時間によって音量が変わらないようにするため、収録音声を最初に 48kHz へ統一し、台詞ごとに同じラウドネスへ正規化する。表現としての音量の変化は、その後に `volume` で付ける(台本仕様 §3.6)。Script2Voice のピーク正規化(台詞ごとに最大値を 1.0 にする)は、小さな声も大きな声も同じピークになるため、使わない。

**A. 取り込み(§5.2の3)**
1. 形式の読み込み: WAV(16/24/32bit 整数、32bit 浮動小数)、設定で FLAC。
2. **モノラル前提**: 元音源はモノラルとする。チャンネル数が 1 以外、非有限値(NaN/Inf)を含む、ヘッダが不正なファイルは、`bad_format` としてそのテイクを不足にする。ステレオの自動ダウンミックスはしない(位相の打ち消しとレベル差の問題を避けるため。Script2Voice の「L チャンネルだけ」も使わない)。
3. **サンプルレートは 48000Hz に固定**(定数。設定では変えない)。入力が 48kHz でなければリサンプルする(既存のリサンプラを流用)。入力のサンプルレートは問わない。`timeline.json` の `sample_rate` は 48000。
4. 結果を `work/resampled/<テイク>[.<役>].wav`(モノラル、32bit 浮動小数)に書く。**レベルは変えない**(§5.3・§5.9 の検出しきい値が収録の実レベルに対する値であるため)。切れ目の位置(ms)は変換の前後で変わらない。
5. 役別トラックの長さの検査と無音補完は、変換後に行う(§5.3)。

**B. ラウドネス正規化(§5.2の5)**
1. **測定範囲**: 台詞の使用範囲(`src_start_ms`〜`src_end_ms`)のうち、`trim_threshold_db` を超える音が最初に現れる位置から最後に現れる位置まで(前後のマージン・無音を含めない)。検出は §5.3 と同じ 10ms 窓の RMS。`.cuts` の指定範囲でも同じ。測定範囲が得られなければ(全区間がしきい値以下)、`silent` で不足にする(§5.3)。
2. **測定**: ITU-R BS.1770-4 の K 特性のラウドネス(LUFS)。K フィルタの状態は台詞ごとにゼロから始める。
   - 測定範囲が **400ms 以上**: 400ms ブロック・75% オーバーラップ、絶対ゲート -70 LUFS、相対ゲート -10 LU(完全なブロックのみを使う)。
   - 測定範囲が **400ms 未満**: ブロックを使わず、範囲全体の K 特性平均二乗から求める(ゲートなし)。400ms は固定値(設定では変えない)。
3. **測定不能**: 400ms 以上で、絶対ゲートを超えるブロックが1つもない、または結果が非有限のときは、`unmeasurable` としてそのテイクを不足にする。
4. **ゲイン**: `requested_gain_db = target_lufs − 測定値`。適用するゲインは `norm_gain_db = clamp(requested_gain_db, −max_cut_db, +max_boost_db)`(既定 ±24 dB)。制限に掛かったら `norm_clamped = true` とし、警告する(終了コード 1)。台詞ごとに**1つの固定ゲイン**を掛ける(台詞の内部の抑揚・ダイナミクスは変えない。圧縮や自動ゲイン制御はしない)。
5. **ピーク**: 台詞ごとのピーク制限は行わない。処理は 32bit 浮動小数で行い、クリップしない。ピークの処理はマスターのソフトリミッタ(§5.4)だけが行う。
6. **フェード**: 使用範囲の両端に 5ms の半コサインのフェードを、この工程でだけ掛ける(§5.3 では掛けない)。測定は**フェード前**の音声で行う。台詞が 10ms 未満のときのフェード長は、台詞の長さの半分。
7. 結果を `work/lines/<台詞ID>.wav`(モノラル、32bit 浮動小数。フェード後)に書く。検証用に `[normalize] dump_prefade = true` のとき、フェード直前の音声(ゲイン適用済み)を `work/lines_prefade/<台詞ID>.wav` にも書く(既定 off。キャッシュのキーに含める)。

**C. 音響処理との接続(§5.2の7)**
- 音響処理の入力は B の結果。Script2Voice のピーク正規化(`s / peak`)と、出力ピークが上限を超えたときの台詞ごとのリミッタは行わない(台詞ごとにレベルが変わるため)。
- 基準ゲイン(Script2Voice の `base_norm`)は再較正する。**較正の定義**: 基準の台詞(distance が `reference_dist`、pan 0、height 既定、`volume` 1.0)を、残響なしで音響処理(定位・距離・早期反射)に通した出力の、ステレオのラウドネス(BS.1770 の左右チャンネル加算、**マスター前**)が、**入力のラウドネスと ±0.5 LU で一致**する値とする。入力との比で定義するので、`target_lufs` を変えても再較正は要らない。較正信号は、100Hz〜8kHz に帯域制限した定常のピンクノイズ(5 秒)。回帰テストとして常に検証する(§10 項目 3a)。距離・定位・指向性による音量差は、従来どおりの幾何計算で付く。
- **残響の音量補償**: 残響のある場面は、dry と wet の混合(`dry×(1−actual_wet)`)で基準(残響なし)の台詞より小さくなる。これを戻すため、残響パラメータ(rt60・pre_delay・`actual_wet`)ごとに**固定の補償ゲイン**を掛ける。ゲインは、較正信号(5秒、左右同一)に実際の経路と同じ空気吸収を話者距離(0.5 m 刻み、0〜50 m。左右とも同じ距離)で掛けてから、残響の前後で測ったステレオのラウドネス(BS.1770)の差から求め、パラメータごとにキャッシュする。rt60 は4桁に丸め(残響 IR も丸めた値で作る)、`actual_wet`(dry と wet の混合比)は 0.01 刻みに量子化して [0, 0.9] に収める。補償を測る値と実際に混ぜる値は同じ関数の結果で、キーは(rt60、pre_delay、`actual_wet`、量子化した距離)で、数は有限になる(1組の rt60・pre_delay あたり最大 91 × 101)。信号や台詞には依存しないので、音響処理は入力に対して線形のままである。残響なしの場面には掛けない(ゲイン 1.0)。許容は、同じ早期反射設定で残響なしの出力との差が ±0.5 LU(別の信号でテストで検証)。

**D. 中間ファイルとキャッシュ**
- 出力フォルダ `台本名/work/` に作る: `resampled/`(A の結果)、`lines/`(B の結果)、`cache.json`。
- **キー**: `resampled/` は、収録ファイルの内容ハッシュ(SHA-256)+変換処理のバージョン。`lines/` は、その `resampled/` のキー+使用範囲+`trim_threshold_db`+`target_lufs`+`max_boost_db`/`max_cut_db`+正規化処理のバージョン(測定方式・400ms・フェードを含む)。
- **`cache.json`**: 出力ファイルごとに `key`、出力のバイト数と SHA-256、`lines/` には `measured_lufs`・`requested_gain_db`・`norm_gain_db`・`norm_clamped`・測定範囲(開始・終了サンプル)・警告の一覧を持つ。
- **命中**: キーが一致し、出力ファイルが存在して、バイト数と SHA-256 が一致するとき。命中時も `cache.json` の記録から測定値・ゲイン・警告を再現するので、**警告と終了コードは命中の有無で変わらない**。命中しなければ再生成する。
- **書き込み**: 一時ファイルに書いて rename で確定する。`cache.json` は各出力の確定後に更新する。途中で中断しても、次回は不一致の分が再生成されるだけ。
- **古いファイル**: 実行の最後に、今回の実行で有効だった台詞・テイク以外の `work/lines/`・`work/resampled/` のファイルと `cache.json` の項目を削除する(不足になった台詞の古いファイルを含む)。
- `--no-cache` は命中を使わず、すべて再生成する。結果(音声・`timeline.json`・警告)は通常実行と同じになること(§10)。
- `cache.json` が壊れていたら破棄して全て再生成する(ログに記録)。`work/` に書き込めなければ致命的エラー(終了コード 2)。
- 中間ファイルは再生成できるので、削除してよい。元の収録ファイルは変更しない。

**E. 設定(`config.toml`)**

| キー | 既定 | 有効範囲 | 意味 |
|---|---|---|---|
| `[normalize] target_lufs` | -23.0 | -40〜-10 | 台詞の目標ラウドネス |
| `[normalize] max_boost_db` / `max_cut_db` | 24 / 24 | 0〜48 | ゲインの制限 |
| `[normalize] dump_prefade` | false | true/false | フェード前の音声を `work/lines_prefade/` にも書く(①a の完了条件の検証用) |
| `[mix] master_ceiling_db` | -1.0 | -6〜0 | マスターのソフトリミッタの上限 |

サンプルレート(48kHz)とブロック長(400ms)は固定値で、設定にしない。範囲外の値はエラー(終了コード 2)。

### 5.11 サンプルと時刻の規則

- 内部の位置はすべて 48kHz のサンプル単位の整数で保持する。ミリ秒への変換は、出力(`timeline.json`・SRT・FCPXML)を作るときだけ行う。
- ミリ秒の入力(`.cuts`、`overlap=`、`at=`、`#pause`、各種マージン)は、サンプル = ms × 48 で変換する(端数は出ない)。
- 出力の整数ミリ秒への丸め: 開始の時刻(`src_start_ms`、`start_ms`)は**切り捨て**、終了の時刻(`src_end_ms`、`end_ms`)は**切り上げ**にする(範囲が出力で欠けないように)。`duration_ms` は終了と同じく切り上げ。
- **10ms RMS 窓**(§5.3、§5.10 B): 窓は 480 サンプル、間隔(ホップ)も 480 サンプルで重ならない。起点はトラックの先頭(サンプル 0)。末尾の端数は、実際のサンプル数の短い窓として RMS を求める(音を落とさない)。
- 使用範囲(`.cuts` の指定など)が窓の境界と一致しないとき、境界をまたぐ窓は、使用範囲との交差部分だけの短い窓として RMS を求める(範囲外の音を含めない。①b・①c)。検出位置は交差部分の端を超えない。
- `takes[].trims` の `head_ms`/`tail_ms` は丸めた位置から求める: `head_ms = src_start_ms`(切り捨て済み)、`tail_ms = トラックの全長 ms(切り上げ) − src_end_ms(切り上げ)`。削除量そのものは丸めない。
- 「音が現れる位置」は、しきい値を超えた最初の窓の開始サンプル。「音が消える位置」は、しきい値を超えた最後の窓の終了サンプル(最後の窓が端数なら、その終端)。

- `start_ms`/`end_ms` は、出力音声(`full_dialogue.wav`)上の台詞の位置を示す。
- `src_start_ms`/`src_end_ms` は、元の収録ファイル(役別トラックでは全トラック共通の時間軸)上の使用範囲。同じ `take` の台詞は、録音上のタイミングを保って配置されている。
- `measured_lufs`・`requested_gain_db`・`norm_gain_db`・`norm_clamped` は台詞ごとの正規化の記録(§5.10)。`norm_gain_db` は**実際に適用した(制限後の)ゲイン**で、`requested_gain_db` は目標に合わせるのに必要だったゲイン。制限に掛かった台詞(`norm_clamped: true`)は、目標ラウドネスに届いていない。不足の台詞は、これらがすべて null。数値は有限値のみ。キャッシュの命中は記録に影響しない。`normalize.target_lufs` は全台詞共通の目標。
- `takes[].trims` はトラックごとの先頭・末尾の削除量。台詞ごとの `voice_file`・`trim_head_ms`・`trim_tail_ms` は廃止した(`schema_version` 2。ファイル名は `takes[].files` から引く)。
- **take の所属**: `lines[].take` は、台詞を覆うテイクの ID。重複で複数のテイクが同じ台詞を覆うときは、台本の並びで先頭の台詞が最も早いテイク(同じなら ID の辞書順)を記録し、`reason` を `duplicate` にする。`takes[]` には関係するすべてのテイクを `missing: true` で並べる。同じ範囲の混合と役別が併存するときは、1つのテイクとして記録し、`files` に全ファイルを入れる。
- `missing: true` のとき、`src_start_ms`/`src_end_ms`・`measured_lufs`・各ゲインは null、`take` はそのテイクの ID。①a の単独の台詞では、ファイルが無い(`no_file`)ときも、台詞 ID の `-` を `_` にした名前のテイクを `takes[]` に記録する。`reason` は `no_file` | `duplicate` | `unreadable` | `silent` | `split_failed` | `cuts_invalid` | `order_mismatch` | `sync_mismatch` | `bad_format` | `unmeasurable` のいずれか。
- **①a の `takes[]` の例**(単独ファイル。`tracks` は `[null]`):
  ```jsonc
  { "id": "S01_L003", "tracks": [null], "files": ["S01_L003.wav"],  // 正常
    "trims": [{ "track": null, "head_ms": 210, "tail_ms": 480 }], "missing": false, "reason": null },
  { "id": "S01_L004", "tracks": [null], "files": [], "trims": null,   // ファイルが無い
    "missing": true, "reason": "no_file" },
  { "id": "S01_L005", "tracks": [null], "files": ["S01_L005.wav"], "trims": null,   // ステレオなど
    "missing": true, "reason": "bad_format" },
  { "id": "S01_L006", "tracks": [null], "files": ["S01_L006.wav", "S01_L006.flac"], "trims": null,   // 同じ台詞に複数
    "missing": true, "reason": "duplicate" }
  ```
  不足の `takes[]` は `trims` が null。台詞の `lines[]` は `take` にそのテイクの ID、`track` が null。
- **シーンの時間**: `scenes[].start_ms` はシーンに属する全台詞の開始時刻の最小値(配置の完了後に確定。§5.5)、`end_ms` は最も遅い台詞の終了とする(無言のシーンは `silent: true` で、`start_ms` と `end_ms` は§5.5 のとおり)。複数のシーンにまたがるテイクでは、隣り合うシーンの範囲が重なり得る。シーンの開始時刻は台本の並びで単調非減少(後退すれば①がエラーにする。§5.5)。同じ時刻に始まるシーンが並ぶときは、台本の並びで後ろのシーンを採用する。④は、素材の切り替えを次のシーンの `start_ms` で行う。前のシーンの台詞が次のシーンの開始後も続く場合、その吹き出しをどの素材に重ねるかは④で決める(①の契約は、台詞が属する `scene` を示すだけ)。
- 後方互換: `schema_version` を上げるときは、後続工程が拒否できるようにする。後続工程は未知のバージョンを拒否する。
- この契約の変更は、後続のサブプロジェクトに影響するため High Risk として扱う。

## 7. ②指示書生成(契約のみ)

入力は `timeline.json` の `cast[].appearance` と `scenes[].visual`。AI(Claude Code 等)が読み、画像/動画生成AI向けの指示書をシーンごとに作る。出力は `prompts/S01.md` のような形式(詳細は②の spec で決める)。

素材の置き場所と命名規約: `assets/S01.png` / `assets/S01.mp4`(シーン番号をキーにする)。AIが Higgsfield 等で直接生成・取得した場合も、この場所にこの名前で保存する。Script2Voice の素材解決の優先順(名称一致、番号一致、既定画像)は②/④の spec で整理する。

## 8. ③吹き出し調整(ブラウザGUI)

**ブラウザ上で HTML を直接操作する方式は実現可能で、採用を推奨する。** 理由: レイアウトの描画と直接操作(ドラッグ、リサイズ)は HTML/JS の得意分野で、egui より操作性を作りやすい。動画・音声の再生(`<video>`/`<audio>`)も標準機能で使える。

- `script2video bubbles <台本名>` で、`s2v-bubbles` が `127.0.0.1` の空きポートでローカルサーバを起動し、ブラウザを開く。外部からは接続できない(ループバックのみ、起動ごとのトークン付き)。
- UI は静的な HTML/JS/CSS を実行ファイルに同梱する(ネットワーク上のライブラリに依存しない)。
- 画面: シーンごとに素材を表示し、その上で吹き出しをドラッグして位置を決め、枠でサイズを変え、表示開始/終了の時刻を台詞の長さに合わせて調整する。音声付きでプレビューできる。
- 保存先は `bubbles.json`(台詞IDをキーに、位置・サイズ・尾の向き・表示開始/終了のオフセット)。保存のたびに `.bak` を残す。
- 吹き出しの描画は、プレビュー(ブラウザ)と最終合成(④)で同じ見た目になるようにする。方式は③の spec で決める。

## 9. ④最終合成(契約のみ)

入力: `full_dialogue.wav` + `timeline.json` + `assets/` + `bubbles.json`。出力: 1本の動画(mp4)。`s2v-video`(ffmpeg)を流用して、シーンごとの素材の割り当て、素材が短い場合の静止/ループ、立ち絵、吹き出しの重ね、字幕を合成する。詳細は④の spec で決める。

1. 採番: 挿入・削除・再実行で既存IDが変わらないこと、欠番が再利用されないこと、ID以外のバイトが変わらないこと。
2. 照合: 不足・重複・余剰・形式違いの検出。①a: 単独ファイル(`.wav`/`.flac` の重複を含む)の照合、範囲ファイル名が照合から外れて警告だけになること、範囲ファイルと単独ファイルが併存しても単独ファイルが使われ、単独ファイルが無ければ `no_file` になること。①b・①c: テイクのファイル名の解釈(混合・役別、範囲の展開)。
2a. テイク切り分け(合成波形): 2人会話(混合・役別)、台詞の重なり(役別)、K=1、台詞の途中の長い間(誤分割と曖昧警告)、無音なしの連続発声(発声区間不足でテイク全体が不足)、録音の前後の長い無音(候補から除外)、同率の候補、200ms・しきい値・比 1.3 の境界、整数 ms への丸め、サンプルレートの異なる入力、順序不一致でテイク全体が不足になること。
2b. `.cuts`: 指定範囲の内側だけが無音のとき `silent` で不足になること、`trims` が複数区間でも `head_ms`/`tail_ms` の式どおりになること、共通の端のトリムが行われず指定範囲がそのまま使われること(長さ10000msと10008msの役別トラックで、`.cuts` の終了が10008msのとき)、一部のトラックだけの `.cuts` が不足になること、自動検出より優先されること、検証の各条件(欠落・重複・別の役の ID・開始≧終了・範囲外・重なり・順序違い・書式)ごとの失敗。役別の一部だけの `.cuts` は不可。
2c-1. 切り分けの規則: 役別トラックの長さが10ms以内で異なるとき、長い側の語尾が残り短い側が無音で補われること、台本上で最後の台詞より遅く終わる別の役の台詞があっても、最後の台詞の終了が延びないこと、 小さな声(`take_gate_db` 未満、`trim_threshold_db` 超)のK=1テイクが不足になること、マージンを付けても隣の台詞の範囲と重ならないこと、 役別トラックで台詞内の間(`take_split_min_gap_ms` 以上)が発声区間を分けても1台詞にまとまること(K=1 を含む)、弱い語頭・語尾が `trim_threshold_db` の端の広げで残ること、`.cuts` の使用範囲がそのまま採用されマージンが付かないこと、曖昧判定が両集合が非空のときだけ行われること、同率の候補の選択(録音上で早いもの)。台詞途中の長い間による誤分割は警告されないことがあるため、`Process.log` の一覧に正しい値が出ること。
2c. 範囲: 採番後に挿入された台詞(`L003 → L008 → L004`)を含む範囲、シーンをまたぐ範囲、始点が終点より後ろ、欠番。
2d. 失敗の単位: 部分欠落・部分重複・役別の一部のトラックの破損・同期ずれで、テイク全体が不足になり、終了コード 1 になること。仮の無音が録音位置の次の台詞に食い込まないこと。
2e. 単独ファイルの専用経路(①a): 全体が -45 dBFS の単独ファイルが、`take_gate_db` に関係なく §5.3 の無音削除だけで使われ、不足にならないこと。①b の導入後も同じ結果になること(回帰テスト)。
3. 無音削除: 合成波形で、先頭/末尾の削除量、マージン、全無音、内部無音の保持、元ファイル不変。役別トラックで共通の端が使われ、削除後も各役の発声時刻の差が不変であること。
3a. 入力の変換と正規化(合成信号): 16/24bit 整数・32bit 整数・32bit 浮動小数・44.1/48/96kHz のモノラル入力が 48kHz のモノラルになること。ステレオ・非有限値・壊れたヘッダが `bad_format` で不足になること。音量の異なる(例: -40/-20 dBFS)同じ内容の台詞が、同じ `target_lufs` に正規化されること。台詞内の抑揚が保たれること(1つの固定ゲインであること)。測定範囲にマージン・前後の無音が含まれず、マージンだけ変えてもゲインが変わらないこと。400ms 前後(399/400/401ms、不完全な末尾ブロック)の測定。絶対ゲート未満しか無い台詞が `unmeasurable` になること(単独ファイルで、最初の 400ms が無音で末尾 50ms だけ発声する 450ms の波形は、50ms の発声部分が測定範囲になり測定できること)。ゲインの制限(`requested_gain_db` と `norm_gain_db` の違い、`norm_clamped`、警告)。フェードの測定前後の位置と、10ms 未満の台詞。正規化後に台詞ごとのピーク制限が掛からないこと。**基準ゲインの較正**(基準の台詞のステレオ出力ラウドネスが入力と ±0.5 LU 以内)。マスターのソフトリミッタ(重なり加算・BGM・SE 加算後のピーク、`full_dialogue.wav` が上限を超えないこと、`tracks/*.wav` が浮動小数でクリップしないこと)。変換結果のレベルが入力と同じであること(リサンプル後のゲイン誤差が ±0.1 dB 以内。切り分けしきい値の動作は ①b・①c で検証する)。キャッシュ: 命中と再生成(収録ファイル・設定の変更)、`--no-cache` と通常実行で音声・`timeline.json`・警告・終了コードが一致すること、出力ファイルの欠損・破損・`cache.json` の破損からの復旧、不足になった台詞の古い `work/lines/` の削除、書き込み中断後の再実行。元ファイルの不変。
4. 配置: `overlap`、`at`、`#pause`、SE の台詞基準配置、境界条件(負の開始時刻、未来参照)。テイクの最初の台詞への `at`/`overlap`、テイク内の台詞への外部参照、テイク内の `#pause`/`#se`/`#bgm_*`/`#paragraph`、`cursor` が後退しないこと、先頭の録音無音を二重に数えないこと。
5. 不足時の継続: 仮の無音とフラグ、`reason` の値、終了コード。失敗したテイクでも、内部の `overlap`/`at`/`#pause`/`#bgm_*` を無視すること。重複で複数のテイクが同じ台詞を覆うときの `take`/`takes` の記録。
4a. 配置の基準: 無言のシーン(開始が `cursor`、長さが `#pause` の合計、`@pause paragraph` を加えない、次のシーンの先頭台詞には通常の `@pause paragraph` が掛かる)、台詞も `#pause` もないシーンと `#pause 0` だけのシーンのエラー、同時に始まるシーンが許容され後ろのシーンが採用されること、 通常配置のアンカーが `cursor` を基準にすること(A 0〜5000、B が `at=A+1000` で1000〜2000のあとのテイクは5000以降)、シーン開始が配置完了後の最小開始時刻で確定すること(テイク内の最初の台詞より早い所属台詞が `at=` で置かれる場合)、重複テイク間でアンカーか内部かの判定が1通りになること。 `overlap` が `last_line_end` を基準にし、`cursor` と別であること(A 0〜5000、B が `at=A+1000` で 1000〜2000、C が `overlap=100` なら C は 1900)。台本の並びでシーンの開始が逆転したときのエラー。テイク内の `#bgm_*` の無視。
5a. 出力の一致: `timeline.json` の時刻が、`full_dialogue.wav`・`subtitles.srt`・`timeline.fcpxml` の時刻と一致すること。`src_*` が元ファイルの位置と一致すること。サンプルからミリ秒への丸め(開始は切り捨て、終了は切り上げ)と、10ms 窓の規則(§5.11)の境界値(窓の境目、末尾の端数、1サンプルだけ超える音)、`trims` の丸め(端数が 481 サンプルの場合など)。
6. ゴールデン: 固定の台本と合成wavから `timeline.json` を生成し、期待値と比較する。
7. 流用元の既存テストの移植と通過。

検証コマンド: `cargo fmt --check` / `cargo test --workspace` / `cargo build --workspace`。

## 12. 未決事項(Human 判断待ち)

1. 台本HTMLの印刷レイアウト(縦書き対応の要否)。
2. 同じ台詞を覆う収録ファイルが複数あるときの選択方法(現案はエラー、関係するテイクを不足扱い)。
3. `number` が `.bak` と `.ids` を作る運用でよいか。
4. 無音削除のしきい値(-50 dBFS)、マージン(30/80ms)の既定値。実音声で調整する。
5. テイク切り分けの既定値(`take_gate_db` -40 dBFS、`take_split_min_gap_ms` 200ms、曖昧判定の比 1.3、`sync_tolerance_ms` 10ms)。合成波形のテストでは妥当性を確認できない(漏れ込み・息・弱い子音・収録ノイズ)。**実収録の素材で、混合・役別の各1本以上を使った受け入れ試験に通ること**を、①b(混合)・①c(役別)それぞれの完了条件にする。①a の完了条件は項目 8。
6. `.cuts` の書式(台詞ID 開始ms 終了ms)で足りるか。ブラウザGUI(③)で切れ目を編集する案もある。
7. 役別トラックの同期マーカー(手拍子など)による開始位置の自動検証を入れるか。現案は収録側の責任とし、検証しない。
8. 正規化の目標ラウドネス(-23 LUFS)と、マスターのソフトリミッタの上限(-1.0 dBFS)の既定値。基準ゲインの較正は §5.10 C の定義で行うが、既定値の妥当性は実収録で確認する。**①a の完了条件**: 実収録の素材(複数の収録セッション・音量の異なる台詞を含む)について、`dump_prefade = true` で保存した `work/lines_prefade/` の音声(正規化後・フェード前)を、`cache.json` に記録した測定範囲(開始・終了サンプル)でそのまま再測定し(測定範囲の再検出はしない。増幅後に範囲が変わらないようにするため)、測定範囲が 400ms 以上の台詞の値が、ゲインの制限に掛かった台詞を除いて目標の ±1 LU に入ること。400ms 未満の台詞は、`norm_gain_db` が式(`target_lufs − 測定値`、制限後)どおりであることを合格条件とし、フェード後のラウドネスは問わない。
9. 台詞ごとに正規化を無効にする指定(収録の音量をそのまま使う)を設けるか。現案は設けない(表現の音量は `volume` で付ける)。
10. **残響のある場面の音量**【採用済み(2026-10-14)】: 残響パラメータごとの固定の補償ゲイン(較正信号で求め、線形性は保つ)を掛ける。詳細は §5.10 C。早期反射が支配的な条件(早期反射を極端に強めた小部屋、既定の小さい部屋の距離 10 m)では最大約 0.5 LU の誤差が残る(既知の限界)。(経緯: 現行の音響処理は `dry×(1−actual_wet)` と固定係数(`REVERB_WET_GAIN` = 0.4)の wet を合成するため、残響なしの基準の台詞より最大約 3 LU 小さくなっていた。)
