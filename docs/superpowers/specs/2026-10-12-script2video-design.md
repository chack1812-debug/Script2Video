# Script2Video 設計書

日付: 2026-10-12 / 状態: ドラフト(Human レビュー待ち) / 台本の書式は [台本仕様.md](../../../台本仕様.md)

## 1. 目的

Script2Voice-Rust版から音声合成を外し、**収録した肉声**を起点に、台本から完成動画までを作るパイプラインを新規プロジェクトとして作る。

流れ: 台本 → 採番 → (収録) → 音声連結・計時・音響効果 → 情景から指示書を生成(AI) → 挿絵・動画クリップの生成 → 台詞の吹き出しの重ね合わせ(ブラウザGUI) → 最終合成(1本の動画)。

## 2. 分解

独立した4つのサブプロジェクトに分け、それぞれ spec → 計画 → 実装のサイクルを回す。

| # | サブプロジェクト | 工程 | 本書の扱い |
|---|---|---|---|
| ① | 台本+音声パイプライン (`number` / `build`) | 採番、音声連結、無音削除、計時、音響効果、`timeline.json` | **詳細設計** |
| ② | 指示書生成 | 情景・人物像から画像/動画生成AIへの指示書を作る。AIが素材を直接生成・取得する場合の受け渡し | 契約のみ(§7) |
| ③ | 吹き出し調整(ブラウザGUI) | 素材に台詞の吹き出しを重ね、位置・表示時間を調整 | 方式のみ(§8) |
| ④ | 最終合成 | 音声+挿絵+動画クリップ+吹き出しを1本の動画にする | 契約のみ(§9) |

サブプロジェクト間の契約は、①が出力する `timeline.json`(§6)、③が出力する `bubbles.json`、②/④が使う素材フォルダである。

## 3. 前提と決定事項

- 実装言語は **Rust**。Script2Voice-Rust版(`D:\UDS\宇摩コードワークス\Script2Voice-Rust版`)のクレートをコピーして改造する。リポジトリは `D:\UDS\宇摩コードワークス\Script2Video`、Script2Voice は現状維持とする。
- 音声合成エンジン(`s2v-engines`)は持たない。
- 画像・動画の生成そのものは外部ツールで行う。Higgsfield のように AI から操作できるツールでは、AI(Claude Code 等)が生成・取得を直接行う場合がある。本体は生成を行わず、指示書の元データ、素材の置き場所、命名規約を提供する。
- 台本のシーン番号は `#paragraph`(カット)単位、台詞番号は台本全体で一意(台本仕様 §1)。

## 4. リポジトリ構成

Cargo ワークスペース。

| クレート | 由来 | 役割 |
|---|---|---|
| `s2v-core` | Rust版を改造 | 台本パーサ、採番、タイムライン、型。エンジン関連を除去 |
| `s2v-audio` | Rust版を流用 | リサンプル、正規化、定位、残響。無音削除を追加 |
| `s2v-export` | Rust版を流用 | SRT、FCPXML、`timeline.json`、台本HTML |
| `s2v-video` | Rust版を流用 | ffmpeg による合成(④) |
| `s2v-bubbles` | 新規 | ブラウザGUI用のローカルサーバ(③) |
| `s2v-cli` | Rust版 `src/main.rs` を改造 | コマンド `number` / `build` / `bubbles` / `compose` |

流用元の移植は、元のコミットを記録した上でコピーし、元のテストも一緒に移す。以後は独立して進化させる。

## 5. ①の詳細設計

### 5.1 `number`
台本仕様 §4 のとおり。台本に ID を書き込み、`台本名.html`(印刷・閲覧用)を出力する。

`台本名.html` の内容: タイトル、登場人物(役名・話者名・外見描写)、シーンごとの見出し(番号・名称・情景)、台詞の表(台詞ID・役名・台詞)。印刷向けスタイルを `@media print` で用意し、ブラウザの印刷で紙・PDFにできる。

### 5.2 `build`: 処理の順序

1. **パース**。台本を読み、役・シーン・台詞・コマンドの列を得る。
2. **照合**。`--voice-dir` の収録ファイルを台詞IDで台詞に対応付ける。不足・重複・形式エラーを集める。
3. **読み込みと無音削除**(§5.3)。
4. **配置**。台詞の開始時刻を決める(§5.5)。
5. **音響処理**。台詞ごとにリサンプル、正規化、定位、残響を適用する(既存のDSPの順序をそのまま使う)。
6. **ミックス**。台詞・BGM・SE をそれぞれ別トラックに加算し、`full_dialogue.wav` に合成する(§5.4)。
7. **出力**。`timeline.json`、SRT、FCPXML、トラック別wav、`Process.log`。

### 5.3 収録音声の前後の無音削除

- 検出は 10ms 窓の RMS で行い、しきい値は既定 -50 dBFS(`config.toml` の `trim_threshold_db`)。
- 先頭は最初に音が現れる位置の `trim_head_margin_ms`(既定 30ms)手前、末尾は最後に音がある位置の `trim_tail_margin_ms`(既定 80ms)後までを残す。語頭の子音・語尾の余韻の欠けを避ける。
- 切り口に 5ms のフェードを入れてクリックを防ぐ。
- **元の収録ファイルは変更しない**。削除はメモリ上で行う。
- 全区間がしきい値以下なら、その台詞は「無音ファイル」として不足と同じ扱いにする。
- 削除した量は `timeline.json` に `trim_head_ms` / `trim_tail_ms` として残す。
- 長さの計測と開始時刻の計算は、削除後の長さを基準にする。
- 内部の無音(台詞の途中の間)は削除しない。

### 5.4 トラックとミックス

| トラック | 内容 |
|---|---|
| dialogue | 台詞(重なりは加算) |
| bgm | `#bgm_start` / `#bgm_stop` |
| se | `#se`(台詞にかぶせた配置を含む) |

`full_dialogue.wav` は3トラックの合成。トラック別 wav も同時に出力し、動画編集ソフトで別トラックに載せられるようにする。加算時のクリップは、トラックごとの音量補正とマスターのソフトリミッタで防ぐ。

### 5.5 台詞の配置

- 基準時刻 `cursor` は直前の台詞の終了時刻とする(最初は 0)。
- 通常の台詞は `cursor + 無音` で開始する。無音は、話者が同じなら `@pause sentence`、交替なら `@pause cast`、シーンの先頭なら `@pause paragraph` とする(Script2Voice と同じ)。
- `overlap=N` の台詞は `cursor - N` で開始し、無音は入れない。`cursor - N < 0` ならエラーにして 0 に丸める。
- `at=台詞ID+N` の台詞は、参照した台詞の開始時刻+N で開始する。参照先が不足していた場合、仮の無音の長さを基準にする(§5.6)。
- 台詞を置いたあと、`cursor` は「ここまでに置いた全台詞の終了時刻の最大値」に更新する。
- `#pause N` は `cursor` を N ms進める。

### 5.6 不足した収録の扱い(処理は継続)

- 不足・形式エラー・無音ファイルの台詞は、エラーメッセージを `Process.log` と標準エラーに出す。処理は止めない。
- 仮の長さは、台詞の文字数×`placeholder_ms_per_char`(既定 200ms)とし、無音で埋める。
- `timeline.json` では `missing: true`、`reason` を付ける。字幕は出力する。
- 終了コード: 0=全件OK、1=警告・不足あり(出力は完成)、2=台本の構文エラー等(出力なし)。

### 5.7 エラー処理まとめ

| 事象 | 処理 | 終了コード |
|---|---|---|
| 収録ファイル不足/形式エラー/無音 | 仮の無音で継続 | 1 |
| 同一台詞IDのファイルが複数 | その台詞を不足扱いで継続。ファイル名を列挙 | 1 |
| 台本にない台詞IDのファイル | 警告して無視 | 1 |
| BGM/SE ファイルが見つからない | その命令を無視して継続 | 1 |
| ID重複、`at` が未来参照、`overlap` と `at` の併用、未定義の役名 | エラー。出力しない | 2 |

### 5.8 流用元の変更点

| 流用元 | 変更 |
|---|---|
| `s2v-core` パーサ | `@cast` の簡素化、台詞ID・`overlap`/`at`・`#visual`・`#paragraph[Sxx]`・`#se` オプションの追加、読み指定の削除 |
| `s2v-core` タイムライン | 重なり・`at` 配置、SE の台詞基準配置 |
| `s2v-audio` | 無音削除の追加。リサンプル以降は変更なし |
| `s2v-export` | `timeline.json` のスキーマ拡張、台本HTMLの追加 |

## 6. `timeline.json`(後続工程との契約)

```jsonc
{
  "schema_version": 1,
  "script": "台本名.txt",
  "sample_rate": 48000,
  "duration_ms": 123456,
  "cast": [
    { "name": "A", "speaker": "田中", "appearance": "30代の男性。短髪。紺のスーツ。" }
  ],
  "scenes": [
    {
      "id": "S01", "name": "港の朝", "index": 1,
      "start_ms": 0, "end_ms": 20500,
      "visual": { "text": "朝焼けの港。…", "kind": "image" }   // kind: image | video | null
    }
  ],
  "lines": [
    {
      "id": "S01-L003", "scene": "S01", "cast": "A", "text": "おはよう。",
      "start_ms": 1200, "end_ms": 2750,
      "voice_file": "S01_L003.wav",
      "trim_head_ms": 210, "trim_tail_ms": 480,
      "missing": false
    }
  ],
  "events": [
    { "type": "se", "file": "door.wav", "start_ms": 1500, "gain_db": 0 },
    { "type": "bgm_start", "file": "bgm01.wav", "start_ms": 0 },
    { "type": "bgm_stop", "start_ms": 40000 }
  ]
}
```

- 時刻はすべて整数ミリ秒。`lines` の順序は台本の並びに従い、開始時刻で並べ替えない。
- `start_ms`/`end_ms` は無音削除後の台詞の位置を示す。
- 後方互換: `schema_version` を上げるときは、後続工程が拒否できるようにする。
- この契約の変更は、後続のサブプロジェクトに影響するため High Risk として扱う。

## 7. ②指示書生成(契約のみ)

入力は `timeline.json` の `cast[].appearance` と `scenes[].visual`。AI(Claude Code 等)が読み、画像/動画生成AI向けの指示書をシーンごとに作る。出力は `prompts/S01.md` のような形式(詳細は②の spec で決める)。

素材の置き場所と命名規約: `assets/S01.png` / `assets/S01.mp4`(シーン番号をキーにする)。AIが Higgsfield 等で直接生成・取得した場合も、この場所にこの名前で保存する。Script2Voice の素材解決の優先順(名称一致、番号一致、既定画像)は②/④の spec で整理する。

## 8. ③吹き出し調整(ブラウザGUI)

**ブラウザ上で HTML を直接操作する方式は実現可能で、採用を推奨する。** 理由: レイアウトの描画と直接操作(ドラッグ、リサイズ)は HTML/JS の得意分野で、egui より操作性を作りやすい。動画・音声の再生(`<video>`/`<audio>`)も標準機能で使える。

- `script2video bubbles <台本名>` で、`s2v-bubbles` が `127.0.0.1` の空きポートでローカルサーバを起動し、ブラウザを開く。外部からは接続できない(ループバックのみ、起動ごとのトークン付き)。
- UI は静的な HTML/JS/CSS を実行ファイルに同梱する(ネットワーク上のライブラリに依存しない)。
- 画面: シーンごとに素材を表示し、その上で吹き出しをドラッグして位置を決め、枠でサイズを変え、表示開始/終了の時刻を台詞の長さに合わせて調整する。音声付きでプレビューできる。
- 保存先は `bubbles.json`(台詞IDをキーに、位置・サイズ・尾の向き・表示開始/終了のオフセット)。保存のたびに `.bak` を残す。
- 吹き出しの描画は、プレビュー(ブラウザ)と最終合成(④)で同じ見た目になるようにする。方式は③の spec で決める。

## 9. ④最終合成(契約のみ)

入力: `full_dialogue.wav` + `timeline.json` + `assets/` + `bubbles.json`。出力: 1本の動画(mp4)。`s2v-video`(ffmpeg)を流用して、シーンごとの素材の割り当て、素材が短い場合の静止/ループ、立ち絵、吹き出しの重ね、字幕を合成する。詳細は④の spec で決める。

## 10. テスト方針(①)

1. 採番: 挿入・削除・再実行で既存IDが変わらないこと、欠番が再利用されないこと、ID以外のバイトが変わらないこと。
2. 照合: 不足・重複・余剰・形式違いの検出。
3. 無音削除: 合成波形で、先頭/末尾の削除量、マージン、全無音、内部無音の保持、元ファイル不変。
4. 配置: `overlap`、`at`、`#pause`、SE の台詞基準配置、境界条件(負の開始時刻、未来参照)。
5. 不足時の継続: 仮の無音とフラグ、終了コード。
6. ゴールデン: 固定の台本と合成wavから `timeline.json` を生成し、期待値と比較する。
7. 流用元の既存テストの移植と通過。

検証コマンド: `cargo fmt --check` / `cargo test --workspace` / `cargo build --workspace`。
