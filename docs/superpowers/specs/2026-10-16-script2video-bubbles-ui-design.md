# Script2Video ③ bubbles の画面(計画 2d-2)設計メモ

正本は `2026-10-14-script2video-video-design.md`(以下「設計書」)の §5.3(画面)と §5.4(API の型の表が唯一の定義)。2d-1 でサーバー・API・仮の画面ができている。このメモは 2026-10-16 のブレインストーミングで決めたことと理由を残す。決定は設計書の §5.3・§8・§10 に反映済み。

## 目的と成功の条件

- 2d-1 の API の上に、§5.3 の画面の本体を作る。人がブラウザで吹き出し・ト書きを動かし、大きさ・尻尾・表示時刻の offset を調整して `bubbles.json` に保存する。
- 成功の条件: 設計書 §9「GUI で見た配置と `render` の結果の同じ時刻のコマが一致する」。§8 の Chrome の自動操作で、主な操作と、台詞の `<script>` などが文字として表示されることを確かめる。

## 決めたこと

| 論点 | 決定 | 理由・却下した案 |
|---|---|---|
| JS の組み立てとテスト | DOM に触れない純粋なモジュール(`geom`・`timeline`・`model`)と、DOM・通信(`api`・`view`・`app`)に分ける。純粋なモジュールは Node の `node:test` で単体テストし、`cargo test` から `node --test` を呼ぶ(Node が無ければ失敗、`S2V_SKIP_NODE_TESTS=1` のときだけ飛ばす)。画面全体は Chrome の自動操作 | 依存を足さずに、ドラッグの計算・再生の同期・未保存の判定を細かく固定するため。却下: 1 ファイルで Chrome の確認だけ(固定できない)、Node のテストを手動にする(忘れる) |
| 重ね画像の取得 | 項目ごとに `/api/render` の PNG を画面側で覚えておく。手動の配置を変えたら `/api/layout` を呼び、配置の結果(位置・大きさ・尻尾・切り詰め)が変わった項目の PNG だけを捨てる | サーバーを変えずに済み、ドラッグのたびの合成を避ける。却下: コマごとにサーバーで合成(重い、API が増える)、起動時に全部取る(項目が多いと遅い) |
| 再生中の動画の素材 | 動画も再生し、音声の位置から求めたコマ n の素材の中のコマ k と、動画の位置(k/fps)が 2 コマ以上ずれたら合わせ直す。カットの切り替えでも合わせる。最後のコマで止める素材は最後で一時停止 | 滑らかに見せるため。却下: コマごとにシーク(カクつく)、再生中は止める(見え方を確かめられない) |
| 計画の分け方 | 2d-2 は 1 つの計画(6 タスク前後: 純粋なモジュール 3 つ、表示、操作、Chrome の確認) | 2d-1 で API の安全面は固まっている |

## 構成

- `crates/s2v-bubbles/src/assets/` に ES モジュール: `geom.js`(純粋: 画面と canvas の換算、ドラッグの計算(移動・四隅の大きさ・尻尾)、画面の内側に収める、矢印キー)、`timeline.js`(純粋: コマ n から表示中のカットと項目、`order` の順、素材の中のコマ k(サーバーと同じ式)、音声の位置から n、動画のずれの判定)、`model.js`(純粋: 手動配置の一式、未保存の判定、自動配置に戻す、layout の結果との比較で捨てる PNG の決定、offset の入力の検証、要求の番号による古い結果の破棄)、`api.js`(fetch の包み)、`view.js`(DOM。文字は `textContent` だけ)、`app.js`(入口)。
- サーバーは埋め込みのファイルとパスを足すだけ(`text/javascript; charset=utf-8`)。API は変えない。
- テスト: `crates/s2v-bubbles/assets-test/*.test.mjs`(`node --test`)、Rust のテスト(`node --test` の呼び出し、全 JS に `innerHTML`・`eval`・`new Function`・インラインのハンドラが無いこと、index.html にインラインのスクリプト・スタイルが無いこと)。

## データの流れと操作

- **起動**: `/api/state` を取り、一覧・スライダー(`0..total_frames`)・プレビューを作る。手動配置の一式を `state.items[].manual` から作り「保存済み」とする。
- **コマの移動**(スライダー・一覧の選択・再生): (1) `timeline.js` で現在のカットと表示中の項目、(2) 背景(画像は `<img>` に fit と余白の色、動画は `<video>` の位置を k/fps 秒、読み込みエラーのカットは `/media/frame?n=` の PNG、素材なしは「素材なし」)、(3) 表示中の項目の PNG(無ければ `/api/render`)、(4) `order` の順に `配置の左上 + X-S2V-Origin` へ重ねる。
- **再生**: `<audio>` で `full_dialogue.wav`、`requestAnimationFrame` ごとに音声の位置から n。動画は上の決定どおり。
- **操作と確定**: 選択は一覧かプレビューの枠のクリック(重なっていれば最前面)。ドラッグ中は輪郭だけ(本体=移動、四隅=大きさ、尻尾の先端)。手を離したら手動配置の一式を仮に更新し、`/api/render`(その項目)と `/api/layout`(全体)。422 ならその項目を直前の確定値に戻して理由を表示。成功なら確定し、配置の結果が変わった項目の PNG を捨てる。数値の欄は Enter かフォーカスが外れたときに同じ手順。矢印キーは 1px(Shift で 10px)、確定は 300ms 空けてから。「自動配置に戻す」は一式から項目を消して同じ手順。保存(ボタン・Ctrl+S)は `/api/save`、成功で「保存済み」、422 は理由の一覧。
- **終了**: 未保存なら確認してから `/api/quit`、「終了しました」と表示。`beforeunload` は未保存のときだけ確認。
- **表示**: 手動配置の印、切り詰めの印、警告の一覧、未保存の表示。

## エラー処理

- API の失敗: 403 は「セッションが切れました。bubbles を起動し直してください」、422 は理由を出して元に戻す、500・503 は短い文で操作は続けられる。失敗した PNG の取得は覚えず、次に表示するときに取り直す。
- 素材: `<video>` のエラーで `/media/frame` へ。frame も失敗したら「プレビューできません」。
- 同時の要求: 確定の要求(render・layout)が返る前に次の確定が来たら、古い結果は捨てる(要求ごとの番号で最新だけを反映)。

## テスト

- `node:test`: `geom`(換算の往復、四隅のドラッグで大きさが負や画面外にならない、尻尾が画面の内側、矢印キーで端を越えない)、`timeline`(カットの境目のコマ n0−1・n0・n1−1・n1、項目の表示の範囲の境目(半開区間)、`order` の順、素材の中のコマの式(止める・ループ。サーバーのテストと同じ値)、音声の位置からのコマ(floor)、ずれの判定)、`model`(未保存、自動に戻す、捨てる PNG、offset の検証、古い要求の結果の破棄)。
- Rust: `node --test` の呼び出し、JS の禁止の検査、index.html の検査。
- Chrome の自動操作(最後のタスク。コントローラーが実施): 台詞に `<script>alert(1)</script>` などを含む台本で build → `bubbles --no-open` → Chrome で開き、文字として表示される、ドラッグで移動・大きさ・尻尾を変えて保存すると `bubbles.json` に入る、小さすぎる大きさが元に戻る、スライダーと再生で吹き出しが出入りする。GUI と render のコマの一致は、同じコマの GUI のスクリーンショットと `render` の出力のコマを並べて目で比べる(厳密な一致は 2d-1 のテスト「`state` のコマの範囲と `render` の切り替えのコマの一致」が担う)。
