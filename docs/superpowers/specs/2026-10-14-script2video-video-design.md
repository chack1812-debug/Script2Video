# Script2Video 映像工程(②③④)設計書

日付: 2026-10-14 / 状態: 承認済み(2026-10-14、節ごとに Human が承認)。Codex(gpt-5.6-sol)のレビューを反映(同日) / 前提: [設計書(①)](2026-10-12-script2video-design.md)、[台本仕様.md](../../../台本仕様.md)

本書は、①の設計書 §7〜§9(契約のみ)を置き換える。②プロンプト生成、③吹き出し・ト書きの配置、④最終合成を定める。①の `timeline.json` は本書の §3 で v3 に拡張する。

## 1. 目的と決定事項

肉声から作った `full_dialogue.wav` と台本から、完成動画 `output.mp4` を作る。Script2Voice の肉声版に当たる。

Human の決定(2026-10-14):

| 項目 | 決定 |
|---|---|
| 画面の構成 | 挿絵または動画クリップを全面に出し、その上に**吹き出し**(台詞)と**ト書き**(四角い枠)を重ねる。**字幕は付けない**。立ち絵は使わない |
| 文字の向き | 吹き出しの台詞もト書きも**縦書き** |
| ト書きの入力 | 台本に `#note` で書き、位置・大きさは③の GUI で調整する |
| ト書きの表示時間 | 書いた位置から、次の区切り(次の `#note`・`#cut`・シーンの終わり)まで |
| ②の範囲 | **プロンプトの生成まで**。画像・動画の生成は人(または AI が外部ツール)で行い、決められた名前で置く。本体は生成 API を呼ばない |
| 素材の単位 | シーンごと。`#cut` でシーン内の素材を切り替えられる |
| 動画素材が短いとき | 最後のコマで止める(既定)。`loop` 指定でループ。長いときは切り詰める |
| 吹き出しの大きさの調整 | 文字の大きさは一定(設定値)。吹き出しの大きさを変えると折り返しが変わる。文字が入りきらない大きさにはできない |
| 描画方式 | Rust で吹き出し・ト書きを PNG に描き(縦書きの組版を含む)、④はそれを ffmpeg で重ね、③の GUI は同じ PNG を表示する。描画のコードを1つにして、プレビューと完成動画の見た目を一致させる |
| 古い完成動画 | `build` が前回の成果物を無効にする時点で、`output.mp4` を `output.stale.mp4` に改名する |
| 同名シーンの素材共用 | 行わない(Script2Voice との違い)。素材はカット ID の名前だけで探す |
| 実装の順 | 計画 2a(④)→ 2b(②)→ 2c(③) |

## 2. コマンドと構成

| コマンド | 段階 | 入力 | 出力 |
|---|---|---|---|
| `number` | 既存(拡張) | 台本 | 番号付きの台本。`#cut`・`#note` にも番号を付ける |
| `build` | ①(拡張) | 台本、`voices/` | 既存の出力。`timeline.json` を v3 にする |
| `prompts` | ② 新規 | `timeline/timeline.json` | `prompts/S01.md` …、`prompts/index.md` |
| `bubbles` | ③ 新規 | `timeline/timeline.json`、`tracks/` の素材、`full_dialogue.wav`、`bubbles.json` | `bubbles.json`(+ `bubbles.json.bak`) |
| `render` | ④ 新規 | `full_dialogue.wav`、`timeline/timeline.json`、`tracks/` の素材、`bubbles.json`(任意) | `output.mp4` |

すべて `script2video <コマンド> <台本ファイル>` の形で、台本フォルダを基準にする。

### 2.1 クレート

| クレート | 役割 |
|---|---|
| `s2v-core`(既存) | `#cut`・`#note` の解析と採番、カットとト書きの時刻 |
| `s2v-export`(既存) | `timeline.json` v3 の書き出し |
| `s2v-render`(新規) | `timeline.json` v3 の読み込みと検証、縦書きの組版、吹き出し・ト書きの PNG の描画、自動配置、`bubbles.json` の型と検証、素材の照合。③と④が共用する |
| `s2v-video`(新規) | ffmpeg による合成(④)。Script2Voice の `s2v-video` の考え方を参考に、新しく書く |
| `s2v-bubbles`(新規) | ③のローカルサーバーと埋め込みの HTML/JS/CSS |
| `s2v-cli`(既存) | コマンド `prompts`・`bubbles`・`render` の追加、台本フォルダのロック、Process.log の追記 |

### 2.2 台本フォルダの構成(追加分)

```
台本フォルダ/
  台本.txt
  full_dialogue.wav
  output.mp4          ← render が出力
  output.stale.mp4    ← build が古い output.mp4 を改名したもの
  bubbles.json        ← bubbles が出力(.bak も)
  Process.log
  .script2video.lock  ← 実行中のロック(§2.3)
  prompts/            ← prompts が出力
    index.md
    S01.md
  timeline/timeline.json
  tracks/
    dialogue.wav bgm.wav se.wav   ← build が出力
    S01.png  S01_C02.mp4 …        ← 人が置く素材
  work/render/        ← render の中間ファイル
```

- `build` が `tracks/` で書き換え・削除するのは、自分の出力する wav(`dialogue.wav`・`bgm.wav`・`se.wav`)だけで、素材には触れない。`bubbles.json`・`prompts/` にも触れない。
- `build` は、前回の成果物を無効にする時点(コミットポイント。①の設計書 §5.2)で `output.mp4` があれば `output.stale.mp4` に改名する(前の `output.stale.mp4` は上書き)。改名できなければ エラー 2(コミットポイントの前なので何も変えない)。
- 削除・作り直しをする場所(`prompts/` の生成ファイル、`work/render/`)は、既存の安全検査(①の `layout`)の対象に加える。リンク(シンボリックリンク・ジャンクション)や台本フォルダの外を指していれば、何も消さずに エラー 2。再帰的な削除は、検査を通った固定のパス(`work/render/`)に限る。

### 2.3 ロックとログ

- **ロック**: `number`・`build`・`prompts`・`bubbles`・`render` は、開始時に台本フォルダの `.script2video.lock` に OS の排他ロック(プロセスが終われば自動で外れるもの)を取り、終了まで保持する。取れなければ「別の script2video が実行中」と表示して エラー 2(何も変えない)。`bubbles` は起動中ずっと保持する(GUI を開いたまま `build` はできない)。
- **Process.log**: `build` は作り直す(既存どおり)。`prompts`・`bubbles`・`render` は、`== render 2026-10-14 12:34:56 ==` のような区切りの行を付けて**追記**する。UTF-8、行ごとに書き込む。ログの作り直しと追記は別の関数に分ける。

### 2.4 鮮度の検査(後続コマンド共通)

`prompts`・`bubbles`・`render` は、開始時に次を検査する。

| 検査 | `prompts` | `bubbles`・`render` |
|---|---|---|
| `timeline/timeline.json` が無い、または `schema_version` が 3 でない、または §3.6 の検証に通らない | エラー 2 | エラー 2 |
| 台本ファイルの SHA-256 が `script_sha256` と違う(`build` 後に台本が変わった) | 警告 | 警告 |
| `full_dialogue.wav` の SHA-256 が `audio_sha256` と違う | — | エラー 2 |
| `duration_ms` が 0 | — | エラー 2 |

SHA-256 は、ファイルの生のバイト列に対して計算し、64 文字の小文字の16進で表す。

## 3. 台本の追加命令と `timeline.json` v3

### 3.1 `#cut`

```
#paragraph[S02] 港の朝
#visual 朝焼けの港。漁船が並ぶ。
#note[N01] 翌朝、港。
[S02-L001] A:おはよう
#cut[C02]
#visual (video loop) 波が岸壁に打ち寄せる。
[S02-L002] B:早いね
#note[N02] 二人は黙って海を見る。
#pause 2000
```

- `#cut` はシーンの中で素材を切り替える。シーンの頭は暗黙のカット `C01` で、台本には書かない(`#cut[C01]` はエラー)。
- `[C02]` は `number` が書き込む。カット番号は**シーンごとに** `C02` から振る。人は省略してよい。完全な ID は `S02-C02`。
- `#cut` の後ろに番号以外を書くとエラー。
- `#visual` は、直前の `#cut`(無ければシーンの頭のカット `C01`)に属する。
- `#visual` の印: 行頭の括弧の中に、空白区切りで `image`・`video`・`loop` を書ける(`(video loop)`)。未知の語はエラー。同じカットに `#visual` が複数あれば、本文を改行で連結し、印はまとめて検証する: `image` と `video` が(同じ行でも別の行でも)両方現れればエラー、`loop` はどれかにあれば有効。`loop` は種類が無い・`image` でも書ける(素材が画像なら無視する)。

### 3.2 `#note`

- `#note 本文` はト書き。本文(前後の空白を除く)は空にできない(エラー)。
- `[N01]` は `number` が書き込む。ト書き番号は**シーンごとに** `N01` から振る。完全な ID は `S02-N01`。
- 本文は1行で書く。縦書きの折り返しは自動で行う。

### 3.3 採番(`number`)の拡張

- `#cut` と `#note` に番号を書き込む。規則は台詞と同じ: 既存の番号は変えない、欠番を詰めない、シーンの中で再利用しない、重複はエラー、ID のシーン部分と所属シーンの食い違いはエラー(`#cut`・`#note` の番号はシーン部分を持たないので、所属シーンで決まる)。
- `.ids` に `max_cut.S01=<n>` と `max_note.S01=<n>` を追加する(1シーン1行。`S00` も同じ書式)。`max_cut` は `C01` を予約済みとみなすので、最初に振る番号は2。台詞・カット・ト書きの最大値は独立に管理する。
- `.ids` の未知のキーの行は、書き戻すときにそのまま残す。
- `.ids` と台本の書き換えは、一時ファイルに書いてから置き換える。

### 3.4 時刻

用語: **現在位置**は、その行を処理する時点の `cursor`(①の設計書 §5.5)とする。すなわち、ここまでに置いた全台詞の終了時刻の最大値(重ねた台詞を含む)に、その後の `#pause` を足したもの。直前の台詞の終了時刻(`last_line_end`、`overlap` の基準)とは別である。`@pause` の文間・話者交替の間は、次の台詞を置くときに加わるので、現在位置には含まない。`#se` の既定の位置も同じ定義である(台本仕様 §2.7 をこの定義に統一した)。

- **シーンの映像区間**: シーンの並びで i 番目のシーンの映像区間を `[vs_i, vs_{i+1})` とする。`vs_1 = 0`、`vs_i = scenes[i].start_ms`(i ≧ 2)、最後のシーンの終わりは `duration_ms`。
- **カット**: `C01` はシーンの映像区間の始めから始まる。`#cut` のカットは、その行の現在位置から始まり、シーンの映像区間の内側に収める(始めより前なら始めに、終わりより後なら終わりにする)。各カットは次のカットの始め、またはシーンの映像区間の終わりまで続く。
- **ト書き**: その行の現在位置から始まり、シーンの映像区間の内側に収める(カットと同じ)。終わりは、同じシーンの次の `#note` の始め、次のカットの始め、シーンの映像区間の終わりのうち最も早いもの。
- **吹き出し**: 台詞の `start_ms` から `end_ms` まで表示する。`bubbles.json` の `start_offset_ms`・`end_offset_ms` で前後を調整できる(§5.2)。重なった台詞は吹き出しも同時に出る。不足(`missing: true`)の台詞も、仮の無音の位置に吹き出しを出す。
- 吹き出しとト書きは、カットやシーンの区切りをまたいで表示してよい(絶対時刻で重ねる)。

**境界条件**(期待結果):

| 入力 | 結果 |
|---|---|
| `#cut` がシーンの最初の台詞より前(`#paragraph` の直後) | `C01` が長さ 0(警告しない)、`#cut` のカットがシーンの頭から |
| 同じ現在位置に `#cut` が2つ以上 | 先のカットが長さ 0(警告)、最後のカットが有効 |
| 同じ現在位置に `#note` が2つ以上 | 先のト書きが長さ 0(警告して表示しない) |
| 最後のシーンの最後の台詞の後に `#cut`・`#note`(後ろに `#pause` が無い) | 長さ 0(警告) |
| `#cut`・`#note` の後に `#pause 2000` | その 2000ms の間も表示される(無言の間に見せる書き方) |
| 同じ時刻に始まるシーンが続く | 前のシーンの映像区間が長さ 0(警告。そのシーンのカット・ト書きはすべて長さ 0) |
| 無言のシーン | 台詞のあるシーンと同じ規則 |
| 最初の `#paragraph` より前の `#cut`・`#note` | 暗黙のシーン `S00` に属する。`S00` に台詞が無ければ(`S00` が存在しない)エラー 2 |
| 前のシーンの台詞が次のシーンの開始後まで続く | 吹き出しは絶対時刻で、次のシーンの素材の上にも出る。プロンプトの登場人物には両方のカットで数える(§7) |
| `duration_ms` が 0(台詞も `#pause` も無い) | `build` は従来どおり。`prompts` は表だけを出す。`bubbles`・`render` は エラー 2 |

長さ 0 のカット・ト書きは、映像に現れない(区間ファイルも作らない)。

### 3.5 `timeline.json` v3

v2 からの変更点を示す。`schema_version` は 3。

```jsonc
{
  "schema_version": 3,
  "script_sha256": "…",          // build 時点の台本ファイル(§2.4 の定義)
  "audio_sha256": "…",           // build が書いた full_dialogue.wav(§2.4 の定義)
  "scenes": [
    {
      "id": "S02", "name": "港の朝", "index": 2, "silent": false,
      "start_ms": 20500, "end_ms": 41000,
      "cuts": [
        { "id": "S02-C01", "start_ms": 20500, "end_ms": 30000,
          "visual": { "text": "朝焼けの港。漁船が並ぶ。", "kind": "image", "loop": false } },
        { "id": "S02-C02", "start_ms": 30000, "end_ms": 43000,
          "visual": { "text": "波が岸壁に打ち寄せる。", "kind": "video", "loop": true } }
      ],
      "notes": [
        { "id": "S02-N01", "text": "翌朝、港。", "start_ms": 20500, "end_ms": 30000 }
      ]
    }
  ]
}
```

- v2 の `scenes[].visual` は廃止し、`cuts[].visual` に移す。`#visual` が無いカットは `visual` が null。`kind` は `image` | `video` | null。
- シーンの映像区間は `cuts` の最初の始めから最後の終わりまでで表す(別のフィールドは持たない)。
- 長さ 0 のカット・ト書きも含める(`start_ms == end_ms`)。
- それ以外のフィールド(`lines`・`takes`・`events`・`cast` など)は v2 のまま。

### 3.6 v3 の不変条件

`s2v-render` に v3 の読み込みと検証を置き、`prompts`・`bubbles`・`render` は必ずこれを通す。違反は エラー 2。`build` の書き出しのテストでも同じ検証を使う。

- ID の書式: シーン `^S\d+$`、カット `^S\d+-C\d+$`、ト書き `^S\d+-N\d+$`、台詞 `^S\d+-L\d+$`(桁数は問わない)。カット・ト書き・台詞の ID のシーン部分は、所属するシーンの ID と一致する。
- 一意: シーン・カット・ト書き・台詞の ID は、それぞれ重複しない。
- 順序: `scenes`・`cuts`・`notes`・`lines` は台本の並び。
- 範囲: すべての時刻は `0 ≤ start_ms ≤ end_ms ≤ duration_ms` の整数。
- カット: 各シーンに1つ以上あり、最初は `<シーンID>-C01`。シーンの中でカットは隙間なく続く(`cuts[k].end_ms == cuts[k+1].start_ms`)。最初のシーンの最初のカットは 0 から始まり、シーン i の最後のカットの終わりはシーン i+1 の最初のカットの始めに等しく、最後のシーンの最後のカットは `duration_ms` で終わる。
- ト書き: シーンの中で `start_ms` が単調非減少。各ト書きの `end_ms` は次のト書きの `start_ms` 以下。シーンの映像区間の内側にある。
- 未知のフィールドは無視する(将来の追加のため)。`schema_version` は 3 だけを受け入れる。

## 4. ④最終合成(`render`)

### 4.1 処理の流れ

1. **ロックと検査**: ロックを取る(§2.3)。鮮度の検査(§2.4)。`bubbles.json` があれば読んで検証する(§5.2)。壊れている → エラー 2。無ければ全項目を自動配置にする。ffmpeg・ffprobe を探し(設定のパス、無ければ PATH)、版が 6.0 以上であることを確かめる(無い・古い → エラー 2)。フォントを検査する(§6.4)。
2. **素材の照合**(§4.3)。不足があれば一覧を出して エラー 2。`default_image` が設定されていれば代わりに使い、警告にとどめる。
3. **作業フォルダ**: `work/render/` を作り直す(§2.2 の検査の後)。古い中間ファイルは使い回さない。
4. **吹き出し・ト書きの描画**: 表示する全項目(長さ 0 でないもの)の配置を決め(`bubbles.json` の値、無ければ自動配置 §4.4)、`s2v-render` で透明な PNG を `work/render/overlays/ov_0001.png` …(ASCII の連番)に描く。
5. **カットごとの区間ファイル**: 長さ 0 でないカットごとに ffmpeg を1回呼び、映像だけの区間ファイル `work/render/seg/seg_0001.mp4` …を作る(§4.5)。
6. **連結と音声**: 区間ファイルを連結し(§4.5)、`full_dialogue.wav` を AAC にして多重化し、`work/render/output.tmp.mp4` に書く。
7. **出力の検証**: `output.tmp.mp4` を ffprobe で検証する(§4.6)。通らなければ エラー 2 で、`output.mp4` は変更しない。
8. **置き換え**: 検証を通った `output.tmp.mp4` を `output.mp4` へ rename で置き換える(Rust の `std::fs::rename` は Windows では既存のファイルを置き換える `MoveFileExW(MOVEFILE_REPLACE_EXISTING)` を使う)。置き換えに失敗したら エラー 2 で、元の `output.mp4` はそのまま残る。成功したら `output.stale.mp4` は消さない(人が消す)。

### 4.2 時刻とコマ

- `frame(t) = floor((t × fps + 500) / 1000)`(t はミリ秒の整数。四捨五入で、0.5 は切り上げ)。動画全体のコマ数は `ceil(duration_ms × fps / 1000)`。
- カットの区間ファイルのコマ数は `frame(end) − frame(start)`(最後のカットだけは 全体のコマ数 − `frame(start)`)。コマ数が 0 になるカットは作らない。境目の絶対時刻を1回だけ丸めるので、カットが多くても誤差は積み重ならず、区間のコマ数の合計は全体のコマ数に等しい。
- 吹き出し・ト書きは、コマ f が `frame(表示開始) ≦ f < frame(表示終了)` のとき表示する。区間ファイルの中では、区間の先頭からの相対コマ番号で指定する。

### 4.3 素材の照合

- 探す場所は `tracks/`。名前は、`C01` は `S01`、それ以外は `S01_C02`(カット ID の `-` を `_` にした形)。拡張子は、画像が `png`・`jpg`・`jpeg`・`webp`、動画が `mp4`・`mov`・`webm`(大文字小文字を区別しない)。
- 同じカットに2つ以上の素材がある(`S01.png` と `S01.mp4` など)→ エラー 2(人が取り除く)。
- `#visual` で明示した種類(`image`/`video`)と素材の種類が違う → エラー 2。種類が未指定なら、素材の拡張子で決める。
- 素材がリンク(シンボリックリンクなど)である、または実体が `tracks/` の外にある → エラー 2。
- 素材の中身(読めるか、映像のストリームがあるか)は ffprobe で確かめる。読めない → エラー 2。

### 4.4 自動配置

`bubbles.json` に無い項目の位置と大きさを決める。同じ入力なら同じ結果になる。

- **大きさ**: §6.2 の `min_size`(1列の高さの上限は、画面の高さ × `bubble_max_height_ratio`、ト書きは `note_max_height_ratio`)。
- **ト書き**: 画面の右上(余白 `margin`)に置く。ト書き同士は時間が重ならない(§3.6)ので、すべて同じ位置になる。
- **吹き出し**: 開始時刻の順(同時なら台本の並び)に1つずつ置く。上端は余白の位置。時間が重なる配置済みの項目(ト書き・先に置いた吹き出し・`bubbles.json` で手動配置した項目)と重ならない最も右の x を、右端から左へ `bubble_gap` ずつずらして探す。どこにも置けなければ右端に置いて警告する。
- **尻尾**: 下向き。吹き出しの下端中央から下へ `tail_length` の点を先端とする(画面の内側に収める)。

### 4.5 ffmpeg の手順

ffmpeg は引数の配列で直接起動する(シェルを経由しない)。作業フォルダ(カレントディレクトリ)は `work/render/seg/`。素材のパスは絶対パスで引数に渡す(日本語を含んでよい)。重ねる PNG と区間ファイルは ASCII の相対名で扱う。フィルタは区間ごとにファイル(`seg_0001.filter`)に書き、ffmpeg 7 以上では `-/filter_complex seg_0001.filter`、6.x では `-filter_complex_script seg_0001.filter` で渡す(コマンドラインの長さの制限を避ける)。

**区間ファイル**(コマ数 N):

- 背景の入力: 画像は `-loop 1 -framerate <fps> -i <素材>`。動画は `-i <素材>`(`loop` のときは前に `-stream_loop -1`)。
- 背景のフィルタ: `setpts=PTS-STARTPTS` → `fps=<fps>` → 画面への収め方(`contain`: `scale=W:H:force_original_aspect_ratio=decrease,pad=W:H:(ow-iw)/2:(oh-ih)/2:color=<background>`、`cover`: `scale=W:H:force_original_aspect_ratio=increase,crop=W:H`)→ `setsar=1` → `format=yuv420p` → 動画で `loop` でなければ `tpad=stop_mode=clone:stop=-1` → `trim=end_frame=N` → `setpts=N/(<fps>*TB)`。
- 重ね: 区間の時間に表示が重なる PNG ごとに `-loop 1 -framerate <fps> -i ../overlays/ov_XXXX.png` を加え、`overlay=x=<x>:y=<y>:eof_action=repeat:enable='between(n,<a>,<b>)'` で順に重ねる(a・b は区間内の相対コマ番号で、b は表示の最後のコマ)。重ねる順は、ト書き → 吹き出し(開始時刻の順)。
- 出力: `-map [v] -an -frames:v N -fps_mode cfr -c:v libx264 -preset <preset> -crf <crf> -profile:v high -pix_fmt yuv420p -colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv -video_track_timescale <fps×1000> seg_XXXX.mp4`。全区間で同じ値を使う。

**連結**: ffprobe で全区間の codec・profile・pix_fmt・幅・高さ・SAR・time base・フレームレート・コマ数(N と一致)を確かめる。

- すべて一致すれば、`concat.txt`(UTF-8、BOM なし、LF。各行 `file 'seg_0001.mp4'` の ASCII の相対名だけ)を作り、`-f concat -safe 0 -i concat.txt -c:v copy` で連結する。
- 一致しなければ、`-c:v libx264`(同じ設定)で再エンコードして連結する。どちらを使ったかは Process.log に書く。

**多重化**: 連結した映像と `full_dialogue.wav` を `-map 0:v -map 1:a -c:v copy -c:a aac -b:a <audio_bitrate> -ar 48000 -ac 2 -movflags +faststart` で `output.tmp.mp4` にする。`-shortest` は使わない(映像のコマ数は音声の長さを切り上げているので、映像の方が1コマ未満だけ長い)。

**性能**: 区間ごとに素材を開き直すので、カット数に比例して時間がかかる。カット数・重ねる PNG の数に上限は設けない。性能の目安は §8 の試験で測り、Process.log に区間ごとの所要時間を書く。

### 4.6 出力の検証

ffprobe で `output.tmp.mp4` を確かめる。

- 映像: H.264、幅・高さ・フレームレートが設定どおり、コマ数が全体のコマ数に等しい。
- 音声: AAC、48000 Hz、2ch。`start_time` の絶対値が 1 AAC フレーム(1024/48000 秒)以内。長さと `duration_ms` の差が 1 AAC フレーム + 1ms 以内。
- 映像と音声の長さの差が 1 コマ + 1 AAC フレーム以内。

## 5. ③吹き出し・ト書きの配置(`bubbles`)

### 5.1 起動と終了

- `script2video bubbles 台本.txt [--port N] [--no-open]`。ロックを取り(§2.3)、`render` の手順 1 と同じ検査をする(素材の不足は起動を妨げず、画面に「素材なし」と表示する)。
- 127.0.0.1 の空いているポート(`--port` で指定可)でサーバーを起動し、既定のブラウザで `http://127.0.0.1:<port>/?token=<トークン>` を開く(`--no-open` なら URL を表示するだけ)。
- 画面の「終了」ボタンか Ctrl+C で終わる。保存していない変更があれば、画面で確認してから終わる。

### 5.2 `bubbles.json`

```json
{
  "version": 1,
  "canvas": { "w": 1920, "h": 1080 },
  "items": {
    "S01-L003": { "kind": "bubble", "x": 1200, "y": 80, "w": 220, "h": 420,
                  "tail": { "dx": 0, "dy": 290 }, "start_offset_ms": 0, "end_offset_ms": 0 },
    "S01-N01":  { "kind": "note", "x": 1700, "y": 40, "w": 160, "h": 380,
                  "start_offset_ms": 0, "end_offset_ms": 0 }
  }
}
```

- 鍵は台詞 ID・ト書き ID。`kind` は ID の種類と一致しなければならない(`L` は bubble、`N` は note)。
- `x`・`y` は左上の座標、`w`・`h` は大きさ(`canvas` 上の整数ピクセル)。`tail` は吹き出しの中心からの尻尾の先端の相対位置。null なら尻尾なし。ト書きは `tail` を持たない。
- **上限**: 枠は画面の内側(`0 ≤ x`、`x + w ≤ canvas.w`、y も同様)。尻尾の先端も画面の内側。`|offset| ≤ 60000`。`items` は 10000 件まで。`canvas` は §4.7 の解像度の範囲。計算はあふれを検査する。
- **手動配置の項目だけを保存する**。GUI で触っていない項目は保存せず、毎回自動配置する(§4.4。手動配置の項目は障害物として扱う)。GUI の「自動配置に戻す」は項目を削除する。
- **解像度が違うとき**: 設定の解像度と `canvas` の縦横比が同じ(`w × H == h × W`)なら、座標・大きさ・尻尾を比で拡大・縮小する(四捨五入)。縦横比が違えば エラー 2。
- 表示時刻は、元の時刻に offset を足し、`[0, duration_ms]` に収める。結果の開始が終了以上になる項目 → エラー 2。GUI は保存時に同じ検査をして拒否する。
- 本文が変わり、保存されている大きさが新しい `min_size` より小さい → 足りない方向だけ最小まで広げ(右下へ。画面からはみ出すなら内側へ寄せる)、警告する。
- `timeline.json` に存在しない ID → 警告して無視する。ファイルからは消さない(採番の都合で一時的に消えることがあるため)。
- 未知のキー、負の大きさ、上限の超過、`version` 違い、JSON の破損 → エラー 2。
- 保存は、既存のファイルを `bubbles.json.bak` にコピーしてから、一時ファイルに書いて置き換える。

### 5.3 画面

- **左**: シーン → カット → 台詞・ト書きの一覧。選ぶと、その項目の表示開始の時刻へ移動して選択する。手動配置の項目には印を付ける。
- **中央**: 16:9 の画面(ウィンドウに合わせて縮小表示。座標は `canvas` のピクセルで扱う)。現在の時刻のカットの素材(画像、または動画のその時刻のコマ)を背景に、その時刻に表示中の吹き出しとト書きを、サーバーが描いた PNG で重ねる。
- **下**: 時刻のスライダー、再生/停止。再生中は `full_dialogue.wav` を鳴らし、吹き出しの出入りと動画の素材を同じ時刻に合わせる。
- **右**: 選択中の項目の数値(x、y、w、h、尻尾、表示開始・終了の offset)。数値を直接入力できる。
- **操作**: 本体のドラッグで移動、四隅のドラッグで大きさ(最小より小さくはならない)、尻尾の先端のドラッグ、矢印キーで 1px(Shift で 10px)、「自動配置に戻す」、保存(Ctrl+S)。元に戻す・やり直しは初版では作らない。
- **表示の更新**: ドラッグ中はブラウザが枠の輪郭だけを描く。手を離すとサーバーに PNG を要求して差し替える。
- 台本由来の文字列(台詞、ト書き、シーン名など)は `textContent` でだけ画面に入れる。`innerHTML` は使わない。

### 5.4 サーバーと API

`tiny_http` による同期のサーバー。1つずつ処理する。HTML・JS・CSS は実行ファイルに埋め込み、別々のパスで配信する(外部のライブラリ・CDN を使わない)。

| メソッドとパス | 内容 |
|---|---|
| `GET /?token=<T>` | トークンを確かめ、クッキーに替えて `/` へ 303 で移す |
| `GET /`、`GET /app.js`、`GET /app.css` | 画面 |
| `GET /api/state` | timeline の必要部分、カットごとの素材の URL、現在の `bubbles.json`、各項目の自動配置の結果と `min_size` |
| `POST /api/render` | 1項目の配置(kind、ID、w、h、尻尾)を受け、PNG を返す。`min_size` より小さければ 422 |
| `POST /api/layout` | 手動配置の項目一式を受け、残りの自動配置の結果を返す(保存はしない) |
| `POST /api/save` | 手動配置の項目一式を検証して `bubbles.json` に保存する。不正なら 422 で理由を返す |
| `GET /media/asset/<カットID>` | そのカットの素材 |
| `GET /media/audio` | `full_dialogue.wav` |
| `POST /api/quit` | 終了 |

**安全**:

- 127.0.0.1 だけで待ち受ける。
- **トークン**: 起動ごとに 32 バイトの乱数を作る。`GET /?token=<T>` で正しければ、クッキー `s2v=<T>; HttpOnly; SameSite=Strict; Path=/` を設定し、トークンを含まない `/` へ移す。以降のすべての要求(画面・API・メディア・`/api/quit`)は、このクッキーが無ければ 403。比較は定数時間で行う。
- **Host**: `127.0.0.1:<port>` か `localhost:<port>` でなければ 403(DNS リバインディング対策)。
- **Origin**: `POST` は `Origin` が `http://127.0.0.1:<port>` か `http://localhost:<port>` であることを要求する(無い・違う → 403)。CORS のヘッダーは返さない。
- **POST の本文**: `Content-Type: application/json` だけを受け、1 MiB まで。
- **応答のヘッダー**: `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' blob:; media-src 'self'; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`Cache-Control: no-store`。
- **メディア**: 要求のパスをファイルシステムのパスとして解釈しない。カット ID から、起動時の照合(§4.3。リンクと `tracks/` の外を拒否済み)の結果のファイルを引く。配信の直前に、そのファイルがリンクでないことを再び確かめる。
- **Range**(メディアのみ): `bytes=a-b`・`bytes=a-`・`bytes=-n` の1つの範囲だけを受ける。正しければ 206 と `Content-Range: bytes a-b/長さ`。範囲が複数・書式違い・満たせない・数値があふれる → 416 と `Content-Range: bytes */長さ`。Range が無ければ 200。メディアの応答には常に `Accept-Ranges: bytes` を付ける。

## 6. 描画部品(`s2v-render`)

### 6.1 縦書きの組版

- **単位**: 書記素クラスタ(Unicode の拡張書記素。`unicode-segmentation`)を1文字として扱う。結合文字・異体字セレクタは前の文字と一体で扱う。
- **整形**: フォントを `ttf-parser` で読み、全角の文字の連なりを `rustybuzz` で縦書き方向(`Direction::TopToBottom`)に整形し、`vert` 機能を明示して有効にする(`vrt2` は使わない)。句読点・括弧・長音などの縦書き用の字形と位置は、フォントの `vert` と縦書きの寸法(`vhea`/`vmtx`)に従う。
- **半角の英数字**: 連続する半角数字が2文字以下なら**縦中横**(横書きで整形し、1文字分の枠の中央に収める。幅が1文字分を超えるときは横に縮める)。それ以外の半角の英数字・記号の連なり(3文字以上の数字を含む)は、横書きで整形して時計回りに 90° 回転して並べる(長さは整形した幅)。
- **列**: 列は右から左へ並べる。1列には、枠の内側の高さに収まるだけ文字を入れる。
- **禁則**:
  - 列の頭に置かない文字(行頭禁則): `、。,.・:;?!ー」』)】〉》〕ぁぃぅぇぉっゃゅょゎァィゥェォッャュョヮヵヶ々〜` とその半角・全角の対応する記号。
  - 列の末尾に置かない文字(行末禁則): `「『(【〈《〔`。
  - 手順: 列の末尾が行末禁則の文字なら、それを次の列へ送る。次の列の頭が行頭禁則の文字になるなら、現在の列の最後の文字を次の列へ送る(追い出し)。追い出しは1つの列で2文字まで。それでも解消しなければ、そのまま置く。
- **フォントに無い文字**: `.notdef` の字形で描き、警告する(絵文字も同じ。初版では対応しない)。
- **全角空白**: 1文字分の空きとして扱う。

### 6.2 関数

```rust
pub struct LayoutContext<'a> {
    pub face: &'a FontFace,     // 読み込み済み・検査済みのフォント
    pub font_size: f32,
    pub line_spacing: f32,
    pub padding: u32,
    pub max_inner_h: u32,       // 1列の高さの上限(自動配置と min_size に使う)
}
```

- `layout(ctx, text, inner_w, inner_h) -> Layout`: 列と字形の配置(位置・回転)。
- `min_size(ctx, kind, text) -> (w, h)`: 1列の高さの上限のもとで列数が最小になる組版の、余白を含む外形の大きさ。手動で大きさを決めたときも、`w`・`h` がこれ以上であることを要求する。
- `render(ctx, spec) -> Overlay`: 項目1つの透明な RGBA 画像と、その左上の画面上の位置。画像は尻尾を含む外接矩形で、画面の内側に限る(§5.2 の上限により、画面の大きさを超えない)。
- 描画は `tiny-skia`。字形の輪郭を `ttf-parser` から取り出してパスにする。
- **同じ結果になる範囲**: 同じフォントのバイト列・同じクレートの版・同じ設定・同じ実行環境なら、同じ画素になる。テストはリポジトリに置いたテスト用のフォントで画素を固定する。

### 6.3 形

- 吹き出し: 枠いっぱいの、楕円に近い角丸の縦長の形。尻尾は、本体の縁の2点と先端を結ぶ三角形で、本体と一体の輪郭として縁取りする。
- ト書き: 長方形の枠。

### 6.4 フォントの検査

起動時(`render`・`bubbles`)に次を確かめる。どれかに外れれば エラー 2 で、外れた項目を表示する。

- ファイルが読める。TTC なら `font_index` が収録数の範囲内(範囲外なら収録数と各フェイスの名前を表示する)。
- `vhea`・`vmtx` がある。GSUB に `vert` 機能がある。
- 表示する全文字のうち、フォントに無いものは警告(§6.1)。

## 7. ②プロンプト生成(`prompts`)

- ロックを取り(§2.3)、鮮度の検査をする(§2.4)。
- `prompts/` の中で、自分が作る名前(`index.md` と `^S\d+\.md$`)のファイルだけを消してから書く。それ以外のファイルには触れない。`prompts/` がリンクなら エラー 2。
- シーンごとに `prompts/S01.md` を書く。カットごとに節を分け、各節に次を書く。長さ 0 のカットは節を作らない。
  - 作る素材のファイル名(`tracks/S01.png` など。`kind` が null なら「png か mp4」)。
  - 種類と、動画ならカットの長さ(秒、小数1桁)と `loop` の有無。
  - プロンプト本文: (1) `[prompts]` の `style`、(2) シーン名、(3) カットの `#visual`、(4) 登場人物とその外見(`cast[].appearance`。外見が無い役は名前だけ)、(5) `[prompts]` の `suffix`。
  - **登場人物**: カットの区間と表示区間が交わる台詞(`line.start_ms < cut.end_ms` かつ `cut.start_ms < line.end_ms`)の話者。台本の並びで初出順、重複なし。
- `prompts/index.md`: 全カットの表(カット ID、ファイル名、種類、長さ、素材の有無)。
- 終了コード: 0 成功、1 警告(`#visual` の無いカットがある、台本が `build` 後に変わった)、2 失敗(鮮度の検査、書き込み失敗、ロック)。
- 設定 `[prompts]`: `style`(既定 空)、`suffix`(既定「縦横比 16:9。画像の中に文字・吹き出しを入れない。」)。

## 8. テスト

- **台本と timeline**:
  - `#cut`・`#note`・`#visual` の印の解析と誤り(`#cut` の後ろの文字、`#cut[C01]`、空の `#note`、`image` と `video` の混在(同じ行・別の行)、未知の印、`loop` の集約)。
  - 採番(シーンごとの振り直し、既存番号の保持、欠番、重複、`.ids` の `max_cut`/`max_note`、`S00`、未知のキーの保持)。
  - 時刻: §3.4 の境界条件の表のすべての行。重ねた台詞の後の `#cut`・`#note`・`#se`(長い台詞 A に短い台詞 B を重ね、その直後に置く → 位置は A の終わり)。
  - v3 の書き出しのゴールデン、§3.6 の検証(違反ごとの失敗)、SHA-256。
  - `build` のコミットポイントでの `output.mp4` → `output.stale.mp4` の改名(前の stale の上書き、改名の失敗)。
- **s2v-render**:
  - 組版の結果を数値で固定する(列数、字形の位置、禁則の送りと追い出し、追い出しの上限、縦中横、回転、結合文字・異体字セレクタ)。
  - テスト用のフォントで、句読点・括弧・長音・小書きの仮名の `vert` 後の字形 ID と送り幅・位置を固定する。
  - 最小の大きさ。小さな PNG の画素比較。
  - 自動配置(重ならないこと、手動配置を避けること、置けないときの警告)。
  - `bubbles.json` の検証(上限・あふれ・種類・縦横比・最小への拡大・存在しない ID)。
  - 素材の照合(拡張子の大小、重複、種類違い、リンク)。
  - フォントの検査(範囲外の `font_index`、`vert` が無いフォント)。
  - テスト用のフォントは、OFL のフォントから必要な文字と `vert` を残した部分集合を作り、ライセンスの文書と一緒にリポジトリに置く(システムのフォントに依存しない)。
- **render**:
  - コマの丸め(多数のカットで合計が全体のコマ数に一致することを、ランダムな入力で確かめる)。
  - ffmpeg の引数とフィルタの組み立て(画像・動画・loop・contain/cover・重ね・コマ番号)。
  - **ffmpeg を使う結合テスト**(短い台本、単色の画像、数秒の動画、吹き出し付き、日本語を含むパス): mp4 を作り、§4.6 の検証を通ること、指定の時刻のコマを取り出して吹き出しの画素があること。ffmpeg が無ければテストは**失敗**する。環境変数 `S2V_SKIP_FFMPEG_TESTS=1` のときだけ飛ばす。
  - 検証や置き換えに失敗したとき、元の `output.mp4` が変わらないこと。
  - 区間ファイルが合わないときの再エンコードへの切り替え。
  - 性能試験(`#[ignore]`、手動で実行): 200 カット・1000 吹き出しの台本で完走し、所要時間を記録する。
- **prompts**: 出力の Markdown のゴールデン(登場人物の判定(カットをまたぐ台詞を含む)、`#visual` の無いカット、長さ 0 のカット、自分の作ったファイル以外を消さないこと)。
- **bubbles のサーバー**: トークンとクッキー、Host、Origin、Content-Type、本文の大きさ、CSP などのヘッダー、メディアの照合(リンク、カット ID の不正)、Range(単一・複数・書式違い・満たせない・あふれ)、保存と `.bak`、最小より小さい・offset の逆転・上限超過の拒否、埋め込みの JS に `innerHTML` が無いこと。画面の操作は Chrome の自動操作で確認する(台詞に `<script>` などを含む台本で、文字として表示されること)。
- **ロック**: 2つ目のコマンドがロックを取れずに エラー 2 になること。
- 検証コマンド: `cargo fmt --check` / `cargo clippy --workspace --all-targets -- -D warnings` / `cargo test --workspace`。

## 9. 受け入れ条件

- sample の台本で `number` → `build` → `prompts` → 素材を置く → `bubbles` で調整 → `render` と進め、`output.mp4` ができる。
- 動画で、縦書きの吹き出しが台詞に合わせて出入りし、ト書きの枠が次の区切りまで出ていて、動画の素材が最後のコマで止まる(`loop` ではループする)ことを、Human が目で確認する。
- GUI で見た配置と、`render` の結果の同じ時刻のコマが一致する。
- §8 のテスト(ffmpeg の結合テストを飛ばさずに)と検証コマンドがすべて通る。
