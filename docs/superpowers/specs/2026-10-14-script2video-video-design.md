# Script2Video 映像工程(②③④)設計書

日付: 2026-10-14 / 状態: 承認済み(2026-10-14、節ごとに Human が承認)。Codex(gpt-5.6-sol)のレビューと再レビューを反映(同日) / 前提: [設計書(①)](2026-10-12-script2video-design.md)、[台本仕様.md](../../../台本仕様.md)

本書は、①の設計書 §7〜§9(契約のみ)を置き換える。②プロンプト生成、③吹き出し・ト書きの配置、④最終合成を定める。①の `timeline.json` は本書の §3 で v3 に拡張する。

## 1. 目的と決定事項

肉声から作った `full_dialogue.wav` と台本から、完成動画 `output.mp4` を作る。Script2Voice の肉声版に当たる。

Human の決定(2026-10-14):

| 項目 | 決定 |
|---|---|
| 画面の構成 | 挿絵または動画クリップを全面に出し、その上に**吹き出し**(台詞)と**ト書き**(四角い枠)を重ねる。**字幕は付けない**。立ち絵は使わない |
| 文字の向き | 吹き出しの台詞もト書きも**縦書き** |
| ト書きの入力 | 台本に `#note` で書き、位置・大きさは③の GUI で調整する |
| ト書きの表示時間 | 書いた位置から、次の区切り(次の `#note`・`#cut`・シーンの終わり)まで |
| ②の範囲 | **プロンプトの生成まで**。画像・動画の生成は人(または AI が外部ツール)で行い、決められた名前で置く。本体は生成 API を呼ばない |
| 素材の単位 | シーンごと。`#cut` でシーン内の素材を切り替えられる |
| 動画素材が短いとき | 最後のコマで止める(既定)。`loop` 指定でループ。長いときは切り詰める |
| 吹き出しの大きさの調整 | 文字の大きさは一定(設定値)。吹き出しの大きさを変えると折り返しが変わる。文字が入りきらない大きさにはできない |
| 描画方式 | Rust で吹き出し・ト書きを PNG に描き(縦書きの組版を含む)、④はそれを ffmpeg で重ね、③の GUI は同じ PNG を表示する。描画のコードを1つにして、プレビューと完成動画の見た目を一致させる |
| 古い完成動画 | `build` が前回の成果物を無効にする時点で、`output.mp4` を `output.stale.mp4` に改名する |
| 同名シーンの素材共用 | 行わない(Script2Voice との違い)。素材はカット ID の名前だけで探す |
| 実装の順 | ④(計画 2a・2b)→ ②(2c)→ ③(2d)。§10 |

## 2. コマンドと構成

| コマンド | 段階 | 入力 | 出力 |
|---|---|---|---|
| `number` | 既存(拡張) | 台本 | 番号付きの台本。`#cut`・`#note` にも番号を付ける |
| `build` | ①(拡張) | 台本、`voices/` | 既存の出力。`timeline.json` を v3 にする |
| `prompts` | ② 新規 | `timeline/timeline.json` | `prompts/S01.md` …、`prompts/index.md` |
| `bubbles` | ③ 新規 | `timeline/timeline.json`、`tracks/` の素材、`full_dialogue.wav`、`bubbles.json` | `bubbles.json`(+ `bubbles.json.bak`) |
| `render` | ④ 新規 | `full_dialogue.wav`、`timeline/timeline.json`、`tracks/` の素材、`bubbles.json`(任意) | `output.mp4` |

すべて `script2video <コマンド> <台本ファイル>` の形で、台本フォルダを基準にする。

### 2.1 クレート

| クレート | 役割 |
|---|---|
| `s2v-core`(既存) | `#cut`・`#note` の解析と採番、カットとト書きの時刻 |
| `s2v-timeline`(新規) | `timeline.json` v3 の**公開の型**(serde の Serialize と Deserialize)と検証 `validate()`(§3.6)。書き出す側(`s2v-export`)も読む側(`prompts`・`bubbles`・`render`)も、この型だけを使う |
| `s2v-export`(既存) | `timeline.json` v3 の書き出し(`s2v-timeline` の型を組み立てて書く。書く前に `validate()` を通す) |
| `s2v-render`(新規) | 縦書きの組版、吹き出し・ト書きの PNG の描画、自動配置、`bubbles.json` の型と検証、素材の照合。項目の組み立て・配置・描画の手順(`scene`)も持ち、③と④は同じ関数だけを使う(GUI と出力の配置の一致を構造で保証する) |
| `s2v-video`(新規) | ffmpeg による合成(④)。Script2Voice の `s2v-video` の考え方を参考に、新しく書く |
| `s2v-bubbles`(新規) | ③のローカルサーバーと埋め込みの HTML/JS/CSS。起動時の検査は `s2v-cli` の `render` と共通の関数(`prepare`)で行う |
| `s2v-cli`(既存) | コマンド `prompts`・`bubbles`・`render` の追加、台本フォルダのロック、Process.log の追記 |

### 2.2 台本フォルダの構成(追加分)

```
台本フォルダ/
  台本.txt
  full_dialogue.wav
  output.mp4          ← render が出力
  output.stale.mp4    ← build が古い output.mp4 を改名したもの
  bubbles.json        ← bubbles が出力(.bak も)
  Process.log
  .script2video.lock  ← 実行中のロック(§2.3)
  prompts/            ← prompts が出力
    index.md
    S01.md
  timeline/timeline.json
  tracks/
    dialogue.wav bgm.wav se.wav   ← build が出力
    S01.png  S01_C02.mp4 …        ← 人が置く素材
  work/render/        ← render の中間ファイル
```

- `build` が `tracks/` で書き換え・削除するのは、自分の出力する wav(`dialogue.wav`・`bgm.wav`・`se.wav`)だけで、素材には触れない。`bubbles.json`・`prompts/` にも触れない。
- `build` は、前回の成果物を無効にする時点(コミットポイント。①の設計書 §5.2)で `output.mp4` があれば `output.stale.mp4` に改名する(前の `output.stale.mp4` は上書き)。改名できなければ エラー 2 で、`output.mp4` と前回の最終成果物は変更しない(ロックの取得と `Process.log` の作り直しは、それより前に済んでいる)。
- **予約名**: 既存の予約名(`full_dialogue.wav`・`Process.log`・`output.mp4`)に、`output.stale.mp4`・`bubbles.json`・`bubbles.json.bak`・`.script2video.lock`・`prompts` を加える(大文字小文字を区別しない)。台本のファイル名が予約名のどれかなら、どのコマンドも何も変えずに エラー 2。台本フォルダに `prompts` という名前のファイル(フォルダでないもの)があれば、`prompts` は エラー 2。
- 削除・作り直しをする場所(`prompts/` の生成ファイル、`work/render/`)は、既存の安全検査(①の `layout`)の対象に加える。リンク(シンボリックリンク・ジャンクション)や台本フォルダの外を指していれば、何も消さずに エラー 2。再帰的な削除は、検査を通った固定のパス(`work/render/`)に限る。

### 2.3 ロックとログ

- **ロック**: `number`・`build`・`prompts`・`bubbles`・`render` は、開始時に台本フォルダの `.script2video.lock` に OS の排他ロック(プロセスが終われば自動で外れるもの)を取り、終了まで保持する。取れなければ「別の script2video が実行中」と表示して エラー 2(何も変えない)。`bubbles` は起動中ずっと保持する(GUI を開いたまま `build` はできない)。
- **Process.log**: `build` は作り直す(既存どおり)。`prompts`・`bubbles`・`render` は、`== render 2026-10-14 12:34:56 ==` のような区切りの行を付けて**追記**する。UTF-8、行ごとに書き込む。ログの作り直しと追記は別の関数に分ける。

### 2.4 鮮度の検査(後続コマンド共通)

`prompts`・`bubbles`・`render` は、開始時に次を検査する。

| 検査 | `prompts` | `bubbles`・`render` |
|---|---|---|
| `timeline/timeline.json` が無い、または `schema_version` が 3 でない、または §3.6 の検証に通らない | エラー 2 | エラー 2 |
| 台本ファイルの SHA-256 が `script_sha256` と違う(`build` 後に台本が変わった) | 警告 | 警告 |
| `full_dialogue.wav` の SHA-256 が `audio_sha256` と違う | — | エラー 2 |
| `duration_ms` が 0 | — | エラー 2 |

SHA-256 は、ファイルの生のバイト列に対して計算し、64 文字の小文字の16進で表す。

## 3. 台本の追加命令と `timeline.json` v3

### 3.1 `#cut`

```
#paragraph[S02] 港の朝
#visual 朝焼けの港。漁船が並ぶ。
#note[N01] 翌朝、港。
[S02-L001] A:おはよう
#cut[C02]
#visual (video loop) 波が岸壁に打ち寄せる。
[S02-L002] B:早いね
#note[N02] 二人は黙って海を見る。
#pause 2000
```

- `#cut` はシーンの中で素材を切り替える。シーンの頭は暗黙のカット `C01` で、台本には書かない(`#cut[C01]` はエラー)。
- `[C02]` は `number` が書き込む。カット番号は**シーンごとに** `C02` から振る。人は省略してよい。完全な ID は `S02-C02`。
- `#cut` の後ろに番号以外を書くとエラー。
- `#visual` は、直前の `#cut`(無ければシーンの頭のカット `C01`)に属する。
- `#visual` の印: 行頭の括弧の中に、空白区切りで `image`・`video`・`loop` を書ける(`(video loop)`)。未知の語はエラー。同じカットに `#visual` が複数あれば、本文を改行で連結し、印はまとめて検証する: `image` と `video` が(同じ行でも別の行でも)両方現れればエラー、`loop` はどれかにあれば有効。`loop` は種類が無い・`image` でも書ける(素材が画像なら無視する)。

### 3.2 `#note`

- `#note 本文` はト書き。本文(前後の空白を除く)は空にできない(エラー)。
- `[N01]` は `number` が書き込む。ト書き番号は**シーンごとに** `N01` から振る。完全な ID は `S02-N01`。
- 本文は1行で書く。縦書きの折り返しは自動で行う。

### 3.3 採番(`number`)の拡張

- `#cut` と `#note` に番号を書き込む。規則は台詞と同じ: 既存の番号は変えない、欠番を詰めない、シーンの中で再利用しない、重複はエラー、ID のシーン部分と所属シーンの食い違いはエラー(`#cut`・`#note` の番号はシーン部分を持たないので、所属シーンで決まる)。
- `.ids` に `max_cut.S01=<n>` と `max_note.S01=<n>` を追加する(1シーン1行。`S00` も同じ書式)。`max_cut` は `C01` を予約済みとみなすので、最初に振る番号は2。台詞・カット・ト書きの最大値は独立に管理する。
- `.ids` の未知のキーの行は、書き戻すときにそのまま残す。
- `.ids` と台本の書き換えは、一時ファイルに書いてから置き換える。

### 3.4 時刻

用語: **現在位置**は、その行を処理する時点の `cursor`(①の設計書 §5.5)とする。すなわち、ここまでに置いた全台詞の終了時刻の最大値(重ねた台詞を含む)に、その後の `#pause` を足したもの。直前の台詞の終了時刻(`last_line_end`、`overlap` の基準)とは別である。`@pause` の文間・話者交替の間は、次の台詞を置くときに加わるので、現在位置には含まない。`#se` の既定の位置も同じ定義である(台本仕様 §2.7 をこの定義に統一した)。

- **シーンの映像区間**: シーンの並びで i 番目のシーンの映像区間を `[vs_i, vs_{i+1})` とする。`vs_1 = 0`、`vs_i = scenes[i].start_ms`(i ≧ 2)、最後のシーンの終わりは `duration_ms`。
- **カット**: `C01` はシーンの映像区間の始めから始まる。`#cut` のカットは、その行の現在位置から始まり、シーンの映像区間の内側に収める(始めより前なら始めに、終わりより後なら終わりにする)。各カットは次のカットの始め、またはシーンの映像区間の終わりまで続く。
- **ト書き**: その行の現在位置から始まり、シーンの映像区間の内側に収める(カットと同じ)。終わりは、同じシーンの次の `#note` の始め、次のカットの始め、シーンの映像区間の終わりのうち最も早いもの。
- **吹き出し**: 台詞の `start_ms` から `end_ms` まで表示する。`bubbles.json` の `start_offset_ms`・`end_offset_ms` で前後を調整できる(§5.2)。重なった台詞は吹き出しも同時に出る。不足(`missing: true`)の台詞も、仮の無音の位置に吹き出しを出す。
- 吹き出しとト書きは、カットやシーンの区切りをまたいで表示してよい(絶対時刻で重ねる)。

**境界条件**(期待結果):

| 入力 | 結果 |
|---|---|
| `#cut` がシーンの最初の台詞より前(`#paragraph` の直後) | `C01` が長さ 0(警告しない)、`#cut` のカットがシーンの頭から |
| 同じ現在位置に `#cut` が2つ以上 | 先のカットが長さ 0(警告)、最後のカットが有効 |
| 同じ現在位置に `#note` が2つ以上 | 先のト書きが長さ 0(警告して表示しない) |
| 最後のシーンの最後の台詞の後に `#cut`・`#note`(後ろに `#pause` が無い) | 長さ 0(警告) |
| `#cut`・`#note` の後に `#pause 2000` | その 2000ms の間も表示される(無言の間に見せる書き方) |
| 同じ時刻に始まるシーンが続く | 前のシーンの映像区間が長さ 0(警告。そのシーンのカット・ト書きはすべて長さ 0) |
| 無言のシーン | 台詞のあるシーンと同じ規則 |
| 最初の `#paragraph` より前の `#cut`・`#note` | 暗黙のシーン `S00` に属する。`S00` に台詞が無ければ(`S00` が存在しない)エラー 2 |
| 前のシーンの台詞が次のシーンの開始後まで続く | 吹き出しは絶対時刻で、次のシーンの素材の上にも出る。プロンプトの登場人物には両方のカットで数える(§7) |
| `duration_ms` が 0(台詞も `#pause` も無い) | `build` は従来どおり。`prompts` は表だけを出す。`bubbles`・`render` は エラー 2 |

長さ 0 のカット・ト書きは、映像に現れない(カットファイルも作らない)。

### 3.5 `timeline.json` v3

v2 からの変更点を示す。`schema_version` は 3。

```jsonc
{
  "schema_version": 3,
  "script_sha256": "…",          // build 時点の台本ファイル(§2.4 の定義)
  "audio_sha256": "…",           // build が書いた full_dialogue.wav(§2.4 の定義)
  "scenes": [
    {
      "id": "S02", "name": "港の朝", "index": 2, "silent": false,
      "start_ms": 20500, "end_ms": 41000,
      "cuts": [
        { "id": "S02-C01", "start_ms": 20500, "end_ms": 30000,
          "visual": { "text": "朝焼けの港。漁船が並ぶ。", "kind": "image", "loop": false } },
        { "id": "S02-C02", "start_ms": 30000, "end_ms": 43000,
          "visual": { "text": "波が岸壁に打ち寄せる。", "kind": "video", "loop": true } }
      ],
      "notes": [
        { "id": "S02-N01", "text": "翌朝、港。", "start_ms": 20500, "end_ms": 30000 }
      ]
    }
  ]
}
```

- v2 の `scenes[].visual` は廃止し、`cuts[].visual` に移す。`#visual` が無いカットは `visual` が null。`kind` は `image` | `video` | null。
- シーンの映像区間は `cuts` の最初の始めから最後の終わりまでで表す(別のフィールドは持たない)。
- 長さ 0 のカット・ト書きも含める(`start_ms == end_ms`)。
- それ以外のフィールド(`lines`・`takes`・`events`・`cast` など)は v2 のまま。

### 3.6 v3 の不変条件

`s2v-timeline` の `validate()` が検査する。`prompts`・`bubbles`・`render` は読み込み時に必ずこれを通し、違反は エラー 2。`build` は書き出す前にこれを通し、違反は内部の誤りとして エラー 2(`timeline.json` を書かない)。

v3 は、`s2v-timeline` の型として全フィールドを定義する(①の設計書 §6 の v2 のフィールドに、本節と §3.5 の変更を加えたもの)。型は `deny_unknown_fields` を使わず、未知のフィールドは読み捨てる。

- ID の書式: シーン `^S\d+$`、カット `^S\d+-C\d+$`、ト書き `^S\d+-N\d+$`、台詞 `^S\d+-L\d+$`(桁数は問わない)。カット・ト書き・台詞の ID のシーン部分は、所属するシーンの ID と一致する。
- 一意: シーン・カット・ト書き・台詞の ID は、それぞれ重複しない。
- 順序: `scenes`・`cuts`・`notes`・`lines` は台本の並び。
- 範囲: すべての時刻は `0 ≤ start_ms ≤ end_ms ≤ duration_ms` の整数。
- カット: 各シーンに1つ以上あり、最初は `<シーンID>-C01`。シーンの中でカットは隙間なく続く(`cuts[k].end_ms == cuts[k+1].start_ms`)。シーンの映像区間(§3.4)と一致する: 最初のシーンは `cuts[0].start_ms == 0`、2番目以降のシーン i は `cuts[0].start_ms == scenes[i].start_ms`、最後のシーン以外は `cuts.last().end_ms == scenes[i+1].start_ms`、最後のシーンは `cuts.last().end_ms == duration_ms`。
- ト書き: シーンの中で `start_ms` が単調非減少。各ト書きの `end_ms` は次のト書きの `start_ms` 以下。シーンの映像区間の内側にある。
- 参照: `lines[].scene` は `scenes[].id` のどれか。`lines[].cast` は `cast[].name` のどれか。`lines[].take` は `takes[].id` のどれか。`lines` を台本の並びにたどったとき、所属シーンの `scenes` での位置は減らない。
- 台詞: `missing: false` なら `src_start_ms ≤ src_end_ms` と `measured_lufs`・ゲインが有限値。`missing: true` なら `reason` が null でなく、`src_*`・`measured_lufs`・ゲインが null。
- シーン: `index` は台本の並びの 1 からの連番(`S00` があればそれが 1。既存の①の出力と同じ)。`silent: true` のシーンには台詞が無い。
- イベント: `start_ms` は `0 ≤ start_ms ≤ duration_ms`。
- 一意(v2 の部分): `takes[].id`、`cast[].name` はそれぞれ重複しない。
- テイク: `tracks` は1つ以上で重複しない(混合・単独は `[null]` の1つ)。
  - `missing: false` なら `reason` が null、`files.len() == tracks.len() == trims.len()`、`trims[i].track == tracks[i]`。さらに `files[i]` は `tracks[i]` のファイル: `tracks[i]` が null なら、ファイル名(拡張子を除く)が `id` に等しい。役名なら、ファイル名(拡張子を除く)が `<id>.<tracks[i]>` に等しい(台本仕様 §3.1)。ただし比較では、台詞番号・シーン番号の桁数(先頭の 0)と英字の大文字小文字を区別しない(台本仕様 §3.1、README の『桁数は問いません』)。`files` には実ファイル名をそのまま残す。
  - `missing: true` なら `reason` が null でなく、`trims` が null。`files` の件数は `reason` で決まる: `no_file` は 0、`duplicate` は 2 以上、それ以外は 1 以上。
- 台詞のトラック: `lines[].track` は、参照先のテイクの `tracks` のどれか(混合・単独のテイクでは null)。
- 台詞の null の規則: `missing: false` なら `reason` が null、`norm_clamped` が真偽値。`missing: true` なら `norm_clamped` も null。`reason` の値は①の設計書 §6 の列挙のどれか。
- イベント: `type` は `se`・`bgm_start`・`bgm_stop` のどれか。`se` は `file`・`start_ms`・`gain_db`、`bgm_start` は `file`・`start_ms`、`bgm_stop` は `start_ms` を必ず持つ。
- 数値: 時刻・長さは i64 に収まる非負の整数。浮動小数は有限値。
- `schema_version` は 3 だけを受け入れる。
- 実装時に、既存の `build` の出力(①のゴールデン)がこれらをすべて満たすことをテストで確かめる。満たさない項目が見つかったら、不変条件を緩めるか `build` を直すかを Human に確認する。

## 4. ④最終合成(`render`)

### 4.1 処理の流れ

1. **ロックと検査**: ロックを取る(§2.3)。鮮度の検査(§2.4)。`bubbles.json` があれば読んで検証する(§5.2)。壊れている → エラー 2。無ければ全項目を自動配置にする。ffmpeg・ffprobe を探し(設定のパス、無ければ PATH)、版が 6.0 以上であることを確かめる(無い・古い → エラー 2)。フォントを検査する(§6.4)。
2. **素材の照合**(§4.3)。不足があれば一覧を出して エラー 2。`default_image` が設定されていれば代わりに使い、警告にとどめる。
3. **作業フォルダ**: `work/render/` を作り直す(§2.2 の検査の後)。古い中間ファイルは使い回さない。
4. **区間の分割と重ね画像**: 表示する全項目(長さ 0 でないもの)の配置を決め(`bubbles.json` の値、無ければ自動配置 §4.4)、§4.2 の規則で各カットを**区間**に分ける。区間ごとに、表示中の全項目を1枚に合成した画面の大きさの透明な PNG(**重ね画像**、straight alpha の RGBA)を `s2v-render` で `work/render/seg/ov_0001.png` …(ASCII の連番)に描く。表示中の項目が無い区間は、全面透明の共通の画像 `ov_empty.png` を使う。カットごとに、重ね画像を並べた一覧 `ovl_0001.txt`(§4.5)を書く。
5. **カットファイル**: 長さ 0 でない(コマ数が 1 以上の)カットごとに ffmpeg を1回呼び、背景を1回だけ読んで重ね画像の流れを重ね、映像だけの**カットファイル** `work/render/seg/cut_0001.mp4` …を作る(§4.5)。カットどうしは独立なので、設定 `jobs` の数まで同時に実行する。
6. **連結と音声**: カットファイルを連結し(§4.5)、`full_dialogue.wav` を AAC にして多重化し、`work/render/output.tmp.mp4` に書く。
7. **出力の検証**: `output.tmp.mp4` を ffprobe で検証する(§4.6)。通らなければ エラー 2 で、`output.mp4` は変更しない。
8. **置き換え**: 検証を通った `output.tmp.mp4` を `output.mp4` へ rename で置き換える(Rust の `std::fs::rename` は Windows では既存のファイルを置き換える `MoveFileExW(MOVEFILE_REPLACE_EXISTING)` を使う)。置き換えに失敗したら エラー 2 で、元の `output.mp4` はそのまま残る。成功したら `output.stale.mp4` は消さない(人が消す)。

### 4.2 時刻とコマ

- `frame(t) = floor((t × fps + 500) / 1000)`(t はミリ秒の整数。四捨五入で、0.5 は切り上げ)。動画全体のコマ数は `ceil(duration_ms × fps / 1000)`。計算は i128(またはあふれを検査する演算)で行う。`duration_ms` が 24 時間を超える台本は エラー 2(`render`・`bubbles`)。
- カットはコマ `[frame(start), frame(end))` を占める(最後のカットの終わりは全体のコマ数)。吹き出し・ト書きは、コマ `[frame(表示開始), frame(表示終了))` に表示する。どちらも空(始め ≧ 終わり)なら映像に現れない。
- **区間**: 各カットのコマ `[カットの始め, カットの終わり)` を、そのカットの中にある項目の表示の始めと終わりのコマで区切る。1つの区間の中では、表示中の項目の組が変わらない。境目は絶対時刻を1回だけ丸めたコマ番号なので、区間がいくつあっても誤差は積み重ならず、カットのコマ数の合計は全体のコマ数に等しい。
- 区間の位置は、カットの先頭からの相対コマ番号(カット内の開始コマ r_k)で表す。最初の区間は r_0 = 0。
- 動画の素材は、カットの先頭を素材の先頭に合わせる。背景はカットの中で1回だけ読むので、区間の境目で再生は途切れない。

### 4.3 素材の照合

- 探す場所は `tracks/`。名前は、`C01` は `S01`、それ以外は `S01_C02`(カット ID の `-` を `_` にした形)。拡張子は、画像が `png`・`jpg`・`jpeg`(WebP は色の扱いを決めきれないので初版では受け付けない)、動画が `mp4`・`mov`・`webm`(大文字小文字を区別しない)。
- 同じカットに2つ以上の素材がある(`S01.png` と `S01.mp4` など)→ エラー 2(人が取り除く)。
- `#visual` で明示した種類(`image`/`video`)と素材の種類が違う → エラー 2。種類が未指定なら、素材の拡張子で決める。
- 素材がリンク(シンボリックリンクなど)である、または実体が `tracks/` の外にある → エラー 2。
- 素材の中身(読めるか、映像のストリームがあるか)は ffprobe で確かめる。読めない → エラー 2。

### 4.4 自動配置

`bubbles.json` に無い項目の位置と大きさを決める。同じ入力なら同じ結果になる。

- **大きさ**: §6.2 の `min_size`(1列の高さの上限は、画面の高さ × `bubble_max_height_ratio`、ト書きは `note_max_height_ratio`)。
- **ト書き**: 画面の右上(余白 `margin`)に置く。ト書き同士は時間が重ならない(§3.6)ので、すべて同じ位置になる。
- **吹き出し**: 開始時刻の順(同時なら台本の並び)に1つずつ置く。上端は余白の位置。時間が重なる配置済みの項目(ト書き・先に置いた吹き出し・`bubbles.json` で手動配置した項目)と重ならない最も右の x を、右端から左へ `bubble_gap` ずつずらして探す。どこにも置けなければ右端に置いて警告する。
- **尻尾**: 下向き。吹き出しの下端中央から下へ `tail_length` の点を先端とする(画面の内側に収める)。

### 4.5 ffmpeg の手順

ffmpeg は引数の配列で直接起動する(シェルを経由しない)。全ての呼び出しに `-nostdin -hide_banner -n` を付ける(`-n` は既存のファイルを上書きしない。作業フォルダは作り直しているので、出力のファイルが既にあれば内部の誤りとして エラー 2)。作業フォルダ(カレントディレクトリ)は `work/render/seg/`。素材のパスは絶対パスで引数に渡す(日本語を含んでよい)。重ね画像・一覧・カットファイルは ASCII の相対名で扱う。1回の ffmpeg の入力は背景と重ね画像の流れの2つだけなので、コマンドラインは短い。フィルタは引数 `-filter_complex` で渡す。

**重ね画像の一覧**(カットごと、`ovl_XXXX.txt`): concat の一覧(UTF-8、BOM なし、LF)で、区間ごとにその重ね画像を並べる。

```
ffconcat version 1.0
file 'ov_0001.png'
option framerate 60
duration 1.483333
file 'ov_empty.png'
option framerate 60
duration 2.000000
file 'ov_empty.png'
option framerate 60
```

- **時刻の精度**: 全ての `file` に `option framerate <2×fps>` を付ける(最後の再掲の項目も)。付けないと、画像の入力の time base が既定の 1/25 秒になり、concat が足す開始時刻がその精度に丸められて、半コマ手前の切り替えが崩れる。`2×fps` なら time base は `1/(2×fps)` で、半コマの格子の時刻をちょうど表せる。これは重ね画像の切り替えの時刻の表し方だけで、出力の動画のフレームレートは変わらない。重ね画像の流れ(副入力)は `file` ごとに1フレームを持つが、その PTS は切り替えの時刻を表すためだけに使われる。出力のフレームレートは、背景の `fps` フィルタと `-fps_mode cfr` によって設定の `fps`(既定 30)になる。
- 区間の数を m とし、区間 k(0 ≤ k < m)の始まりを `u_0 = 0`、`u_k = (r_k − 0.5) / fps`(1 ≤ k < m)、終わりの時刻を `u_m = N / fps` とする。区間 k の重ね画像は `u_k` から始まる。**切り替えをコマの境目の半コマ手前に置く**ので、コマ r_k には必ず区間 k の画像が、コマ r_k − 1 には区間 k−1 の画像が当たる。
- 区間 k の `duration` は `round_us(u_{k+1}) − round_us(u_k)`(`round_us` はマイクロ秒への四捨五入。差を足し合わせても丸めの誤差が積み重ならない)。小数6桁。
- concat は各画像の開始時刻を time base `1/(2×fps)` の目盛りに丸める。一覧の各フレームの時刻は、目盛りで `0, 2r_1 − 1, …, 2r_{m−1} − 1, 2N` になる(マイクロ秒の丸めの誤差は目盛りの半分よりずっと小さいので、正しい目盛りに丸まる)。最後の `2N` は表示の区間ではなく、concat の終わりを決める番兵(最後の画像の再掲)である。
- 最後の項目は、ffmpeg の concat の仕様に合わせて、最後の画像をもう一度 `duration` なしで書く。

**カットファイル**(コマ数 N):

- 入力 0(背景): 画像は `-loop 1 -framerate <fps> -i <素材>`。動画は `-i <素材>`(`loop` のときは前に `-stream_loop -1`)。
- 入力 1(重ね): `-f concat -safe 0 -i ovl_XXXX.txt`。
- フィルタ(全体):

```
[0:v]setpts=PTS-STARTPTS,fps=<fps>,<収め方>,setsar=1,format=yuv420p<,tpad>,trim=end_frame=N,setpts=PTS-STARTPTS[bg];
[1:v]setpts=PTS-STARTPTS,format=rgba,scale=out_color_matrix=bt709:out_range=tv,format=yuva420p[o];
[bg][o]overlay=x=0:y=0:format=yuv420:alpha=straight:eof_action=repeat:repeatlast=1:shortest=0,format=yuv420p[v]
```

  - `<収め方>`: `contain` は `scale=W:H:force_original_aspect_ratio=decrease<:入力の行列・レンジ>:out_color_matrix=bt709:out_range=tv,pad=W:H:(ow-iw)/2:(oh-ih)/2:color=<background>`、`cover` は `scale=W:H:force_original_aspect_ratio=increase<:入力の行列・レンジ>:out_color_matrix=bt709:out_range=tv,crop=W:H`。`<:入力の行列・レンジ>` は、動画と JPEG の素材のときだけ `:in_color_matrix=<行列>:in_range=<レンジ>`(下の「色」の表の値)。
  - `<,tpad>`: 動画で `loop` でないときだけ `,tpad=stop_mode=clone:stop=-1` を入れる。
  - 重ね画像の流れは、一覧の `file` ごとに1フレームを持ち、その PTS は切り替えの時刻を表す。`overlay` は背景の各コマに、そのコマの時刻以前で最も新しい重ね画像を重ねる。これは FFmpeg 6.0 以上の `overlay`(framesync)の既定の選び方で、オプションでは指定しない(`ts_sync_mode` は FFmpeg 6.0〜7.1 の `overlay` に無い)。この動作は境目のコマの結合テストで固定する。
- 出力: `-map [v] -an -frames:v N -fps_mode cfr -threads <threads> -c:v libx264 -preset <preset> -crf <crf> -profile:v high -pix_fmt yuv420p -colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv -x264-params colorprim=bt709:transfer=bt709 -video_track_timescale <fps×1000> cut_XXXX.mp4`。全カットで同じ値を使う。
- 引数の配列とフィルタの文字列は、関数で組み立て、ゴールデンテストで固定する。

**色**: 色は、原色(primaries)・伝達関数(transfer)・行列(matrix)・レンジ(range)の4項目で決める。出力は4項目とも BT.709(レンジは tv)で、タグも同じ。

| 入力 | 原色 | 伝達関数 | 行列・レンジ(入力として ffmpeg に明示する値) |
|---|---|---|---|
| PNG の画像の素材、重ね画像(RGB/RGBA) | BT.709 とみなす(sRGB と同じ) | 変換しない(下の注) | RGB、full |
| JPEG の画像の素材 | 同上 | 同上 | ffmpeg は YCbCr で復号するので、JFIF の規定どおり行列 `bt470bg`(BT.601)・レンジ `pc` を入力として明示する |
| 動画の素材 | `bt709` か、値が無い・`unknown` なら受け入れる。それ以外は エラー 2 | 同左 | 行列: ffprobe の `color_space`(`bt709`・`bt470bg`・`smpte170m` を受け入れ、値が無い・`unknown` は `bt709`、それ以外は エラー 2)。レンジ: `color_range`(`tv`・`pc`。値が無い・`unknown` は `tv`) |

- **伝達関数の注**: sRGB と BT.709 の伝達関数の違い(主に暗部)は、初版では変換せず、sRGB の画素値をそのまま BT.709 として扱う。動画編集で一般的な扱いで、Human の指定した見た目(挿絵と吹き出し)への影響は小さい。正確な変換が必要になったら、`colorspace` フィルタ(`itrc=srgb`)を加える。この近似は設計上の決定として記録する。
- **変換の明示**: RGB と YCbCr の変換は、すべて `scale` に入力と出力の行列・レンジを明示して行い、ffmpeg が自動で挿入する変換(既定の行列が BT.601 になる)に任せない。
  - 背景(動画): `scale=…:in_color_matrix=<行列>:in_range=<レンジ>:out_color_matrix=bt709:out_range=tv`。
  - 背景(PNG): `scale=…:out_color_matrix=bt709:out_range=tv`(入力は RGB)。
  - 背景(JPEG): `scale=…:in_color_matrix=bt470bg:in_range=pc:out_color_matrix=bt709:out_range=tv`。
  - 重ね画像: `[1:v]setpts=PTS-STARTPTS,format=rgba,scale=out_color_matrix=bt709:out_range=tv,format=yuva420p[o]` とし、`overlay` には `format=yuv420` を指定する(重ね合わせの中で色の変換が起きないようにする)。

**連結**: 各カットファイルを ffprobe(`-count_frames -show_streams -show_data_hash sha256`)で確かめる。

- ストリームが映像1本だけ。
- codec・codec tag・profile・level・pix_fmt・field order・幅・高さ・SAR・色(range・space・transfer・primaries)・time base・フレームレート・extradata のハッシュが全カットで一致する。
- time base が `1/(fps×1000)`、`start_pts` が 0、`duration_ts` が `N × 1000`、`nb_read_frames` が N(すべて整数で比較する)。

すべて満たせば、`concat.txt`(UTF-8、BOM なし、LF。各行 `file 'cut_0001.mp4'` の ASCII の相対名だけ)を作り、`-f concat -safe 0 -i concat.txt -c:v copy` で連結する。満たさないカットがあれば、内部の誤り(全カットを同じ設定で作っているので、起きないはずのこと)として エラー 2 にし、食い違った項目とカットを Process.log に書く。再エンコードによる救済はしない。

**多重化**: 連結した映像と `full_dialogue.wav` を `-map 0:v -map 1:a -c:v copy -c:a aac -profile:a aac_low -b:a <audio_bitrate> -ar 48000 -ac 2 -movflags +faststart` で `output.tmp.mp4` にする。`-shortest` は使わない(映像のコマ数は音声の長さを切り上げているので、映像の方が1コマ未満だけ長い)。

**性能**: ffmpeg の呼び出しはカットの数だけで、背景の素材はカットごとに1回だけ読む。重ね画像の枚数は、おおよそ 吹き出し・ト書きの数 × 2(PNG の書き出しは Rust で行う)。処理時間は動画全体のコマ数に比例する。**CPU の配分**: `jobs`(同時に動かす ffmpeg の数)と、各 ffmpeg の `-threads <threads>`(`threads = max(1, 論理コア数 ÷ jobs)`)で、合計が論理コア数を超えないようにする。§8 の性能試験に合格の基準を置く。Process.log にカットごとの所要時間を書く。

### 4.6 出力の検証

ffprobe で `output.tmp.mp4` を確かめる。

- ストリームが映像1本と音声1本だけ。
- 映像: H.264、幅・高さ・フレームレートが設定どおり、コマ数が全体のコマ数に等しい。
- 音声: AAC-LC、48000 Hz、2ch。さらに、ffmpeg で音声を 48 kHz のモノラル(左右の平均)の PCM に復号して(edit list とエンコーダーの遅延の処理は ffmpeg の復号に任せる)、次を確かめる。
  - サンプル数と `full_dialogue.wav` のサンプル数の差が 1024 サンプル以内。
  - **時刻のずれ**: `full_dialogue.wav` の(同じく左右の平均の)最初の 10 秒(短ければ全体)と、相互相関で最も一致するずれが ±2 サンプル以内。この区間が無音(-60 dBFS 未満)なら、最初に音がある位置から 10 秒を使う。全体が無音なら、この検査は飛ばして Process.log に書く。
- 映像の長さ(コマ数 ÷ fps)と音声の長さ(復号したサンプル数 ÷ 48000)の差が、1 コマ + 1024 サンプル以内。

| `bubble_max_height_ratio` / `note_max_height_ratio` | 0.55 / 0.6 | 自動配置と最小の大きさの、1列の高さの上限 |

範囲外の値、未知の `fit`、色の書式違い(`#RRGGBB` 以外)→ エラー 2。

### 4.8 終了コード

| コード | 条件 |
|---|---|
| 0 | 成功 |
| 1 | 成功したが警告あり(代わりの画像を使った、台本が `build` 後に変わった、`bubbles.json` に存在しない ID がある、自動配置で重なった、最小の大きさへ広げた、長さ 0 のカット・ト書き・シーン、フォントに無い文字がある) |
| 2 | 失敗(ロックが取れない、鮮度の検査、素材の不足・重複・種類違い・リンク・読めない、`bubbles.json` の破損、フォント・ffmpeg が無い・古い、ffmpeg の異常終了、出力の検証の失敗、置き換えの失敗、設定の不正) |

## 5. ③吹き出し・ト書きの配置(`bubbles`)

### 5.1 起動と終了

- `script2video bubbles 台本.txt [--port N] [--no-open]`。ロックを取り(§2.3)、`render` の手順 1 と同じ検査を、同じ関数で行う(ffmpeg・ffprobe の版の検査を含む。無い・古い → エラー 2)。素材の不足は起動を妨げず、画面に「素材なし」と表示する。終了コード: 0 正常終了、1 警告ありで起動した(素材の不足、存在しない ID など)、2 起動前の失敗(検査・ポート・ロック)。
- 127.0.0.1 の空いているポート(`--port` で指定可)でサーバーを起動し、既定のブラウザで `http://127.0.0.1:<port>/?token=<トークン>` を開く(`--no-open` なら URL を表示するだけ)。
- 画面の「終了」ボタンか Ctrl+C で終わる。「終了」ボタンでは、保存していない変更があれば画面で確認してから終わる。Ctrl+C ではサーバーはそのまま終わる(未保存の変更はブラウザにしかないので失われる。画面は `beforeunload` で離れる前に確認する)。
- `--port` のポートが使えなければ エラー 2。省略時は OS に空きポートを選ばせる。ブラウザを開けなければ警告して URL を表示し、待ち受けを続ける。

### 5.2 `bubbles.json`

```json
{
  "version": 1,
  "canvas": { "w": 1920, "h": 1080 },
  "items": {
    "S01-L003": { "kind": "bubble", "x": 1200, "y": 80, "w": 220, "h": 420,
                  "tail": { "dx": 0, "dy": 290 }, "start_offset_ms": 0, "end_offset_ms": 0 },
    "S01-N01":  { "kind": "note", "x": 1700, "y": 40, "w": 160, "h": 380,
                  "start_offset_ms": 0, "end_offset_ms": 0 }
  }
}
```

- 鍵は台詞 ID・ト書き ID。`kind` は ID の種類と一致しなければならない(`L` は bubble、`N` は note)。
- `x`・`y` は左上の座標、`w`・`h` は大きさ(`canvas` 上の整数ピクセル)。`tail` は吹き出しの中心からの尻尾の先端の相対位置。null なら尻尾なし。ト書きは `tail` を持たない。
- **上限**: 枠は画面の内側(`0 ≤ x`、`x + w ≤ canvas.w`、y も同様)。尻尾の先端も画面の内側。`|offset| ≤ 60000`。`items` は 10000 件まで。`canvas` は §4.7 の解像度の範囲。計算はあふれを検査する。
- **手動配置の項目だけを保存する**。GUI で触っていない項目は保存せず、毎回自動配置する(§4.4。手動配置の項目は障害物として扱う)。GUI の「自動配置に戻す」は項目を削除する。
- **解像度が違うとき**: 設定の解像度と `canvas` の縦横比が同じ(`w × H == h × W`)なら、座標・大きさ・尻尾を比で拡大・縮小する(四捨五入)。縦横比が違えば エラー 2。
- 表示時刻は、元の時刻に offset を足し、`[0, duration_ms]` に収める。結果の開始が終了以上になる項目 → エラー 2。GUI は保存時に同じ検査をして拒否する。
- 本文が変わり、保存されている大きさでは `fits` が偽になった → 幅と高さをそれぞれ `max(保存値, min_size の値)` に広げ(右下へ。画面からはみ出すなら内側へ寄せる)、警告する(`min_size` 以上なら必ず収まる)。
- `timeline.json` に存在しない ID → 警告して無視する。ファイルからは消さない(採番の都合で一時的に消えることがあるため)。
- 未知のキー、負の大きさ、上限の超過、`version` 違い、JSON の破損 → エラー 2。
- **保存**(`bubbles` の `/api/save`): `bubbles.json`・`bubbles.json.bak` がリンク(シンボリックリンク・ジャンクション)か、あるのに通常のファイルでない(フォルダなど)なら拒否する(500。何も変えない)。既存の `bubbles.json` があれば、その内容を読んで `bubbles.json.bak` に、同じフォルダに新規作成(`create_new`、乱数の名前)した一時ファイル経由で書いて置き換える。次に、新しい内容を同じ方法で一時ファイルに書いて `bubbles.json` を置き換える。`.bak` の段階で失敗 → 何も変えない。本体の段階で失敗 → `.bak` だけが新しくなり、`bubbles.json` は元のまま。一時ファイルは失敗時に消す。
- **保存の中身**: 要求の手動配置の一式(既知の ID だけ)に、読み込んだ `bubbles.json` にあった `timeline.json` に無い ID の項目(読み込み時に拡大・縮小済み)をそのまま足す。`canvas` は設定の解像度。要求に `timeline.json` に無い ID があれば 422。既知の ID が要求に無ければ、自動配置に戻したものとして保存しない。

### 5.3 画面

- **時刻はコマ番号で扱う**。スライダー・再生・選択の移動は、コマ番号 n(`0 ≤ n < 全体のコマ数`、§4.2)で行う。カットの有効なコマの範囲、各項目の表示のコマの範囲、素材の中の時刻は、`render` と同じ関数(`s2v-render::scene` と `s2v-video::frames`)でサーバーが計算して `/api/state` で渡す。画面はそれを使うだけで、ミリ秒からコマを計算しない(GUI と出力の境目のコマを一致させるため)。
- **左**: シーン → カット → 台詞・ト書きの一覧。選ぶと、その項目の表示開始のコマへ移動して選択する。手動配置の項目には印を付ける。
- **中央**: `canvas` の縦横比の画面(ウィンドウに合わせて縮小表示。座標は `canvas` のピクセルで扱う)。現在のコマのカットの素材(画像、または動画のそのコマ)を、`render` と同じ収め方(`fit` の contain/cover と余白の色。`/api/state` が渡す)で背景に置き、そのコマに表示中の吹き出しとト書きを、サーバーが描いた PNG を、`render` と同じ重ねる順(ト書き → 吹き出し(表示開始の順、同時なら台本の並び))・同じ原点(配置の左上 + PNG の原点のずれ)で重ねる。動画の素材は `<video>` で表示し、読み込みエラー(ブラウザで再生できない)のときだけ、そのカットを `/media/frame` の PNG に切り替える。
- **下**: コマのスライダー、再生/停止。再生中は `full_dialogue.wav` を鳴らし、音声の再生位置から現在のコマを求めて、吹き出しの出入りと動画の素材を合わせる。
- **右**: 選択中の項目の数値(x、y、w、h、尻尾、表示開始・終了の offset)。数値を直接入力できる。
- **操作**: 本体のドラッグで移動、四隅のドラッグで大きさ、尻尾の先端のドラッグ、矢印キーで 1px(Shift で 10px)、「自動配置に戻す」、保存(Ctrl+S)。ドラッグ中はブラウザが枠の輪郭だけを自由に動かして描く。手を離すと `/api/render` を呼び、文字が収まらない(422)ならその項目を直前に確定した値に戻す。元に戻す・やり直しは初版では作らない。
- 台本由来の文字列(台詞、ト書き、シーン名など)は `textContent` でだけ画面に入れる。`innerHTML` は使わない。
- 「終了」ボタン: 保存していない変更があれば確認してから `/api/quit` を呼ぶ。ページを離れるときは `beforeunload` で確認する。

### 5.4 サーバーと API

`tiny_http` によるサーバー。API・画面の要求は1つずつ順に処理する。**メディア**(`/media/asset`・`/media/audio`)の要求だけは要求ごとに別スレッドで応答する(ブラウザの動画・音声の長い Range の読み出しが API を止めないため)。同時に走るメディアのスレッドは 8 本までで、超えたら 503。`/media/frame` は専用のワーカースレッド1本で ffmpeg を1つずつ実行する(主スレッドは要求をワーカーに渡すだけで待たない。ワーカーが使用中なら主スレッドが即座に 503)。ffmpeg には `-threads 2` を付け、1回 10 秒で打ち切り(ワーカーが ffmpeg を止めて 500)、出力は 32 MiB まで(超えたら止めて 500)。HTML・JS・CSS は実行ファイルに埋め込み、別々のパスで配信する(外部のライブラリ・CDN を使わない)。接続数の上限は設けない(`tiny_http` は接続ごとに内部でスレッドを使い、受け付けの前に制限する仕組みを持たない。127.0.0.1 だけで待ち受け、クッキーの無い要求は即座に 403 にするので、残るのは同じ PC のプログラムによる資源の消費で、これは守る相手に含めない)。実装計画の最初のタスクで、この `tiny_http` の挙動を確かめて記録する。

**起動と終了の順**: 待ち受けを用意する(ポートを決める)→ URL を作る → ブラウザを開く(または URL を表示)→ 受け付けのループ(主スレッド)。`/api/quit` と Ctrl+C では、受け付けを止め、メディアのスレッドと ffmpeg を止めて(最大 5 秒待ち、残れば ffmpeg は強制終了)、Process.log に終了を書き、最後にロックを外す。メディアのスレッドは Process.log に直接書かず、主スレッドへ知らせて主スレッドが書く。

**要求と応答の型**(JSON。数値は整数のピクセル・コマ番号・ミリ秒。この表が唯一の定義):

| メソッドとパス | 要求 | 応答 |
|---|---|---|
| `GET /?token=<T>` | — | 正しければクッキーを設定して `/` へ 303。違えば 403(クッキーは設定しない) |
| `GET /`、`GET /app.js`、`GET /app.css` | — | 画面 |
| `GET /api/state` | — | `{canvas:{w,h}, fps, total_frames, fit:"contain"\|"cover", background:"#rrggbb", scenes:[{id, name, cuts:[{id, frames:[n0,n1), asset:{url, kind:"png"\|"jpeg"\|"video", looped, frames, frame_url}\|null}]}], items:[{id, kind:"bubble"\|"note", scene, text, frames:[n0,n1), order, manual:配置\|null, placed:配置, image:{dx,dy,w,h}, min_size:{w,h}, clipped:bool}], warnings:[文字列]}`。`frames` は半開区間、`order` は重ねる順。`asset.frames` は動画の素材の長さを出力の fps のコマ数にしたもの(サーバーが ffprobe の長さから `render` と同じ関数で求める。画像は null)。**素材の中のコマ** k は、カットのコマ n について `d = n − n0` とし、`d < asset.frames` なら `k = d`、そうでなければ `looped` なら `k = d mod asset.frames`、そうでなければ `k = asset.frames − 1`(最後のコマで止める)。`<video>` の再生位置は `k / fps` 秒、`/media/frame` も同じ k を使う。サーバーはこの式を `render` と共通の1つの関数で持ち、画面は同じ式を使う。配置は `{x,y,w,h,tail:{dx,dy}\|null, start_offset_ms, end_offset_ms}` |
| `POST /api/render` | `{id, manual:{ID:配置}}`(画面の現在の手動配置の一式。本文と種類はサーバーが timeline から取る) | `image/png` の本文と、ヘッダー `X-S2V-Origin: <dx>,<dy>`(配置の左上から PNG の左上へのずれ)・`X-S2V-Clipped: 0\|1`。サーバーは `/api/layout` と同じく、この手動配置の一式で全体の配置を共通の `scene` で計算し(自動の項目の位置・切り詰めを含む)、その中の項目 `id` を描く。`id` が `manual` にあり、その大きさで文字が収まらなければ 422 |
| `POST /api/layout` | `{manual:{ID:配置}}` | `/api/state` の `items` と同じ形の全項目の配置の結果(保存はしない) |
| `POST /api/save` | `{manual:{ID:配置}}` | 成功 `{saved:true, warnings:[…]}`。検証に外れれば 422 `{errors:[…]}`(§5.2 の上限・offset の逆転・文字が収まらない・未知の ID・種類の不一致)。保存の失敗は 500 |
| `GET /media/asset/<カットID>` | Range 可 | そのカットの素材 |
| `GET /media/audio` | Range 可 | `full_dialogue.wav` |
| `GET /media/frame/<カットID>?n=<コマ番号>` | — | ブラウザで再生できない動画の素材の、コマ n の画像(`image/png`)。n がそのカットの有効なコマの範囲の外なら 400。素材の中の時刻は `render` と同じ規則(素材の長さを超えたら最後のコマで止める。`loop` ならループする)で、`render` と同じ関数で求める。ffmpeg の失敗・打ち切り・出力の上限は 500(理由は Process.log) |
| `POST /api/quit` | — | `{quitting:true}` を返してから終了の手順に入る |

**入力の検証**: `/api/render`・`/api/layout`・`/api/save` は、画像を作る前に同じ関数で配置を検証する(§5.2 の上限: 枠と尻尾の先端が画面の内側、`|offset| ≤ 60000`、`items` は 10000 件まで、あふれの検査。種類と ID の一致)。外れれば 422。

**エラーの応答**: 403(クッキー・Host・Origin)、404(未知のパス・カット ID・素材なし)、405(メソッド)、400(壊れたクエリ・JSON、範囲外の n)、413(1 MiB 超)、415(Content-Type)、416(Range)、422(検証)、500(ffmpeg・保存の失敗)、503(メディアのスレッド・ffmpeg が上限)。本文に内部のパスやスタックを出さない。

**安全**:

- **守る相手**: 他のウェブページ(ブラウザ経由の CSRF・DNS リバインディング・読み出し)と、他のローカルのサービス・ユーザー。`tracks/` の素材と台本はユーザー自身が置いた信頼できるファイルとみなす(それでも、ffmpeg・ffprobe がネットワークなど別の経路を読まないように制限する)。同じユーザーで動く他のプログラムからは守れない(前提として書く)。
- 127.0.0.1 だけで待ち受ける。
- 応答の本文には内部のパスやスタックを出さない。トークンは Process.log に書かない(表示する URL にだけ含める)。Process.log には要求ごとではなく、起動・保存・終了・失敗(403・500 など)を書く。
- **トークン**: 起動ごとに 32 バイトの乱数(16進 64 文字)を作る。`GET /?token=<T>` で正しければ、クッキー `s2v_<port>=<T>; HttpOnly; SameSite=Strict; Path=/` を設定し、トークンを含まない `/` へ移す(名前にポートを含め、別の台本の `bubbles` を同時に開いても上書きし合わない)。以降のすべての要求(画面・API・メディア・`/api/quit`)は、このクッキーが無ければ 403。比較は定数時間で行う。クッキーは同じホストの別のポートのサービスにも送られる(RFC 6265 §8.5)。これは上の前提(同じユーザーのプログラムからは守れない)に含める。
- **Host**: `127.0.0.1:<port>` か `localhost:<port>` でなければ 403(DNS リバインディング対策)。
- **Origin**: `POST` は `Origin` が `http://127.0.0.1:<port>` か `http://localhost:<port>` であることを要求する(無い・違う → 403)。CORS のヘッダーは返さない。
- **POST の本文**: `Content-Type: application/json` だけを受け、1 MiB まで。
- **応答のヘッダー**: `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' blob:; media-src 'self'; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`Cache-Control: no-store`。
- **メディアの固定**: 要求のパスをファイルシステムのパスとして解釈しない(ID から引く)。起動時の照合(§4.3。リンクと `tracks/` の外を拒否済み)で、各カットの素材と `full_dialogue.wav` を、Windows の共有モードで**読み取りだけを許して**(書き込み・削除・改名を他のプロセスに許さない)開き、`bubbles` の終了まで保持する。配信はそのハンドルから位置を指定して読む(Windows の `seek_read`。短い読み出しは繰り返す)。ffmpeg には同じファイルのパスを渡す(共有モードにより、照合したファイルの内容と ffmpeg が読む内容は同じになる)。この間、ユーザーは素材を上書き・削除・改名できない(差し替えるときは `bubbles` を終えてから。起動後に置いた素材は起動し直すと反映される)。開くときに他のプロセスが書き込みのために開いていれば、その素材は「素材なし」として警告する。
- **ffmpeg・ffprobe の入力の制限**: 素材を読む ffmpeg・ffprobe の全ての呼び出し(`render` を含む)に `-protocol_whitelist file` を付ける。
- `Content-Type` は拡張子で決める(`image/png`・`image/jpeg`・`video/mp4`・`video/quicktime`・`video/webm`・`audio/wav`)。`GET` と `HEAD` に応じる(`HEAD` は本文を返さず、ヘッダーは `GET` と同じ)。
- **Range**(メディアのみ。RFC 9110 に従う): `bytes=a-b`・`bytes=a-`・`bytes=-n` の1つの範囲だけを受ける。長さ L のファイルで、`b ≥ L` なら `b = L−1` に切り詰める。`bytes=-n` は末尾の n バイト(`n > L` なら全体)。満たせる範囲なら 206 と `Content-Range: bytes a-b/L`、`Content-Length: b−a+1`。範囲が複数・書式違い・数値があふれる・`a ≥ L`・`bytes=-0`・L が 0 → 416 と `Content-Range: bytes */L`、`Content-Length: 0`、本文なし。Range が無ければ 200 で全体。メディアの応答には常に `Accept-Ranges: bytes` を付ける。

## 6. 描画部品(`s2v-render`)

### 6.1 縦書きの組版

- **整形**: フォントのバイト列と `font_index` を、`ttf-parser` と `rustybuzz` の両方に同じ値で渡す。全角の文字の連なりを `rustybuzz` で縦書き方向(`Direction::TopToBottom`)に整形する。縦書き用の機能は、選んだフェイスの GSUB に `vrt2` があれば `-vert,+vrt2`(rustybuzz が縦書きで自動的に有効にする `vert` を明示して無効にし、`vrt2` だけを使う。OpenType は2つの同時の適用を禁じている)、無ければ `+vert` を明示する(OpenType の推奨どおり、`vrt2` を優先する)。句読点・括弧・長音などの縦書き用の字形と位置は、その機能と縦書きの寸法(`vhea`/`vmtx`)に従う。
- **単位**: 書記素クラスタ(Unicode の拡張書記素。`unicode-segmentation`)を基本の単位とする。整形の結果、1つの字形のクラスタが複数の書記素にまたがるとき(合字など)は、それらの書記素を1つの単位にまとめる。結合文字・異体字セレクタは前の文字と一体になる。単位の高さは、その単位に属する字形の縦の送り幅の合計。
- **半角の英数字**: 連続する半角数字が2文字以下なら**縦中横**(横書きで整形し、1文字分の枠の中央に収める。幅が1文字分を超えるときは横に縮める)。それ以外の半角の英数字・記号の連なり(3文字以上の数字を含む)は、横書きで整形して時計回りに 90° 回転して並べる(長さは整形した幅)。
- **列**: 列は右から左へ並べる。1列には、枠の内側の高さに収まるだけ文字を入れる。
- **禁則**:
  - 列の頭に置かない文字(行頭禁則): `、。,.・:;?!ー」』)】〉》〕ぁぃぅぇぉっゃゅょゎァィゥェォッャュョヮヵヶ々〜` とその半角・全角の対応する記号。
  - 列の末尾に置かない文字(行末禁則): `「『(【〈《〔`。
  - 手順(決定的。`layout` と `min_size` は同じ手順を使う):
    1. **詰め込み**: 単位を先頭から順に、列の高さが内側の高さを超えない限り現在の列に入れる。入らなければ新しい列を始める(1つの単位が高さを超えるときは、その単位だけの列にする)。
    2. **修復**: 列の境目を、最初の列(右端)と2番目の列の境目から順に1つずつ処理する。境目 k(列 k と列 k+1 の間)について:
       - 列 k の末尾が行末禁則の単位で、列 k に2つ以上の単位があれば、末尾の単位を列 k+1 の頭へ移す。
       - 列 k+1 の頭が行頭禁則の単位である間、列 k に2つ以上の単位があり、この境目での移動が合計2回未満なら、列 k の末尾の単位を列 k+1 の頭へ移す(追い出し)。
       - この境目での移動が終わっても禁則が残っていれば、この境目の移動をすべて取り消し、**この境目の処理を始める直前の状態**に戻す。
       - 列 k+1 が内側の高さを超え、かつ2つ以上の単位を持つ間、末尾の単位を列 k+2 の頭へ移す(列 k+2 が無ければ作る)。単位が1つだけの列は、高さを超えていても移さない。その後、次の境目 k+1 を処理する。
    3. 最後の境目まで処理したら終わる。
- **フォントに無い文字**: `.notdef` の字形で描き、警告する(絵文字も同じ。初版では対応しない)。
- **全角空白**: 1文字分の空きとして扱う。

### 6.2 関数

```rust
pub struct LayoutContext<'a> {
    pub face: &'a FontFace,     // 読み込み済み・検査済みのフォント
    pub font_size: f32,
    pub line_spacing: f32,
    pub padding: u32,
    pub max_inner_h: u32,       // 1列の高さの上限(自動配置と min_size に使う)
}
```

- `layout(ctx, text, inner_w, inner_h) -> Layout`: 列と字形の配置(位置・回転)。
- `min_size(ctx, kind, text) -> (w, h)`: 1列の高さの上限のもとで列数が最小になる組版の、余白を含む外形の大きさ。**自動配置の既定の大きさ**に使う。
- `fits(ctx, kind, text, w, h) -> bool`: 大きさ `w`・`h` の枠の内側で実際に組版し、全ての列の幅の合計が内側の幅に収まり、どの列も内側の高さに収まる(単位が1つだけで高さを超える列が無い)とき真。**手動の大きさの可否はこれで決める**(幅を広げて背を低くする、のような調整ができる)。
- `render(ctx, spec) -> Overlay`: 項目1つの透明な RGBA 画像と、その左上の画面上の位置。画像は尻尾を含む外接矩形で、画面の内側に限る(§5.2 の上限により、画面の大きさを超えない)。
- `composite(overlays, canvas) -> RgbaImage`: 区間に表示中の項目を、画面の大きさの透明な画像に合成する(§4.1 の重ね画像)。重ねる順は、ト書き → 吹き出し(表示開始の順、同時なら台本の並び)。色は straight alpha(乗算済みでない)の RGBA。GUI のプレビューも、同じ `render` の結果をこの順に重ねる。
- 描画は `tiny-skia`。字形の輪郭を `ttf-parser` から取り出してパスにする。
- **同じ結果になる範囲**: 同じフォントのバイト列・同じクレートの版・同じ設定・同じ実行環境なら、同じ画素になる。テストはリポジトリに置いたテスト用のフォントで画素を固定する。

### 6.3 形

- 吹き出し: 枠いっぱいの、楕円に近い角丸の縦長の形。尻尾は、本体の縁の2点と先端を結ぶ三角形で、本体と一体の輪郭として縁取りする。
- ト書き: 長方形の枠。

### 6.4 フォントの検査

起動時(`render`・`bubbles`)に次を確かめる。どれかに外れれば エラー 2 で、外れた項目を表示する。

- ファイルが読める。TTC なら `font_index` が収録数の範囲内(範囲外なら収録数と各フェイスの名前を表示する)。
- `vhea`・`vmtx` がある。GSUB に `vrt2` か `vert` の機能がある(どちらを使うかを Process.log に書く)。
- 表示する全文字のうち、フォントに無いものは警告(§6.1)。

## 7. ②プロンプト生成(`prompts`)

- ロックを取り(§2.3)、鮮度の検査をする(§2.4)。
- `prompts/` の中で、自分が作る名前(`index.md` と `^S\d+\.md$`)のファイルだけを消してから書く。それ以外のファイルには触れない。`prompts/` がリンクなら エラー 2。
- シーンごとに `prompts/S01.md` を書く。カットごとに節を分け、各節に次を書く。長さ 0 のカットは節を作らない。
  - 作る素材のファイル名(`tracks/S01.png` など。`kind` が null なら「png か mp4」)。
  - 種類と、動画ならカットの長さ(秒、小数1桁)と `loop` の有無。
  - プロンプト本文: (1) `[prompts]` の `style`、(2) シーン名、(3) カットの `#visual`、(4) 登場人物とその外見(`cast[].appearance`。外見が無い役は名前だけ)、(5) `[prompts]` の `suffix`。
  - **登場人物**: カットの区間と表示区間が交わる台詞(`line.start_ms < cut.end_ms` かつ `cut.start_ms < line.end_ms`)の話者。台本の並びで初出順、重複なし。
- `prompts/index.md`: 全カットの表(カット ID、ファイル名、種類、長さ、素材の有無)。
- 終了コード: 0 成功、1 警告(`#visual` の無いカットがある、台本が `build` 後に変わった)、2 失敗(鮮度の検査、書き込み失敗、ロック)。
- 設定 `[prompts]`: `style`(既定 空)、`suffix`(既定「縦横比 16:9。画像の中に文字・吹き出しを入れない。」)。

## 8. テスト

- **台本と timeline**:
  - `#cut`・`#note`・`#visual` の印の解析と誤り(`#cut` の後ろの文字、`#cut[C01]`、空の `#note`、`image` と `video` の混在(同じ行・別の行)、未知の印、`loop` の集約)。
  - 採番(シーンごとの振り直し、既存番号の保持、欠番、重複、`.ids` の `max_cut`/`max_note`、`S00`、未知のキーの保持)。
  - 時刻: §3.4 の境界条件の表のすべての行。重ねた台詞の後の `#cut`・`#note`・`#se`(長い台詞 A に短い台詞 B を重ね、その直後に置く → 位置は A の終わり)。
  - v3 の書き出しのゴールデン、§3.6 の検証(違反ごとの失敗)、SHA-256。
  - `build` のコミットポイントでの `output.mp4` → `output.stale.mp4` の改名(前の stale の上書き、改名の失敗)。
- **s2v-render**:
  - 組版の結果を数値で固定する(列数、字形の位置、禁則の送りと追い出し、追い出しの上限、縦中横、回転、結合文字・異体字セレクタ)。
  - テスト用のフォントで、句読点・括弧・長音・小書きの仮名の `vrt2`(または `vert`)適用後の字形 ID と送り幅・位置を固定する。
  - 最小の大きさと `fits`(幅を広げて高さを縮めた大きさが受け入れられること、`min_size` 以上の大きさでは常に真であること)。小さな PNG の画素比較。
  - `vrt2` を持つテスト用のフォントで、`vert` が同時に適用されていないこと(`vert` だけにある置換が起きないこと)。
  - 自動配置(重ならないこと、手動配置を避けること、置けないときの警告)。
  - `bubbles.json` の検証(上限・あふれ・種類・縦横比・最小への拡大・存在しない ID)。
  - 素材の照合(拡張子の大小、重複、種類違い、リンク)。
  - フォントの検査(範囲外の `font_index`、`vrt2`・`vert` が無いフォント、`vrt2` があるときにそれが選ばれること)。
  - 組版の修復の手順(追い出しの取り消し、修復による列のあふれの連鎖、最後の列)。`min_size` と `layout` が同じ列分けになること。
  - 合成(`composite`)の重ねる順。
  - テスト用のフォントは、OFL のフォントから必要な文字と `vrt2`・`vert` を残した部分集合を作り、ライセンスの文書と一緒にリポジトリに置く(システムのフォントに依存しない)。
- **render**:
  - コマの丸めと区間の分割(多数のカット・項目で、カットのコマ数の合計が全体のコマ数に一致し、各区間の中で表示中の項目の組が変わらないことを、ランダムな入力で確かめる)。i128 の計算と 24 時間の上限。
  - 重ね画像の一覧(`ovl_XXXX.txt`)の時刻: 半コマ手前の切り替え、`u_m = N/fps`、マイクロ秒への丸めが積み重ならないこと、全項目の `option framerate`、最後の項目の繰り返し。
  - **重ね画像の流れの時刻**(結合テスト): 一覧を ffprobe で読み、各 PNG のパケットの PTS が time base `1/(2×fps)` の目盛りで `0, 2r_1 − 1, …, 2r_{m−1} − 1, 2N`(最後は番兵)になること(fps 30 と 60 の両方)。
  - 色: BT.709 以外の原色・伝達関数・行列が明示された動画の素材が エラー 2 になり、色情報の無い動画は受け入れられること。色の結合テスト: 既知の色の見本(sRGB の画像、重ね画像の PNG、BT.709 の動画、BT.601(`smpte170m`)の動画、full レンジの動画)で出力のコマを取り出し、BT.709・tv として RGB に戻した値が元の値と ±5(8 bit)以内であること(動画の素材は 8 bit の 4:2:0 を2回通るため。実測で BT.601 の見本 (200,100,50) が (197,96,47) になる)、出力のタグが4項目とも BT.709・tv であること。
  - ffmpeg の引数の配列とフィルタの文字列のゴールデン(画像・動画・loop・contain/cover、`-nostdin`・`-n`・`-threads`)。
  - **区間の境目のコマ**(結合テスト): 1コマごとに表示が切り替わる項目を含む台本で、各コマに正しい重ね画像が当たること(境目の前後のコマを取り出して画素で確かめる)。
  - 動画の素材が、区間の境目で途切れず、最後のコマで止まる・`loop` でループすること(コマ番号を焼き込んだテスト用の動画で確かめる)。
  - HDR・BT.2020 の動画の素材が エラー 2 になること。
  - **ffmpeg を使う結合テスト**(短い台本、単色の画像、数秒の動画、吹き出し付き、日本語を含むパス): mp4 を作り、§4.6 の検証を通ること、指定の時刻のコマを取り出して吹き出しの画素があること。ffmpeg が無ければテストは**失敗**する。環境変数 `S2V_SKIP_FFMPEG_TESTS=1` のときだけ飛ばす。
  - 検証や置き換えに失敗したとき、元の `output.mp4` が変わらないこと。
  - カットファイルの検査に外れたとき エラー 2 になること(検査の関数に、食い違った ffprobe の結果を与える単体テスト)。
  - 音声の検証(サンプル数の比較、相互相関による時刻のずれの検出。わざと 100 サンプルずらした音声で失敗すること)。
  - 性能試験(`#[ignore]`、手動で実行。既定の設定、この開発機): (a) 200 カット・1000 吹き出し・長さ 30 分(素材は画像)、(b) 30 分の動画の素材1つのカットに 1000 吹き出し。どちらも 30 分以内に完走し、ffmpeg を含むプロセス全体のメモリが合計 2 GiB 以内、`work/render/` の大きさが 2 GiB 以内であること。所要時間・メモリ・ディスクを記録する。
- **prompts**: 出力の Markdown のゴールデン(登場人物の判定(カットをまたぐ台詞を含む)、`#visual` の無いカット、長さ 0 のカット、自分の作ったファイル以外を消さないこと)。
- **bubbles のサーバー**: トークンとクッキー、Host、Origin、Content-Type、本文の大きさ、CSP などのヘッダー、メディアの照合(リンク、カット ID の不正)、Range(単一・末尾の切り詰め・`bytes=-n`・`bytes=-0`・複数・書式違い・満たせない・あふれ・空のファイル、206 と 416 の `Content-Length`)、`HEAD`、`Content-Type`、起動後に素材を差し替えても照合時の内容が返ること、保存と `.bak`、文字が収まらない大きさ・offset の逆転・上限超過の拒否、メディアの読み出しの途中でも API が応答すること、並列の Range、`/media/frame` のコマの取り出し・打ち切り・出力の上限、`bubbles` の実行中に素材を上書き・削除・改名できないこと(共有モード)、保存の各段階の失敗の注入、`/api/render` の原点のずれと切り詰め、入力の検証(上限・あふれ)、`/api/state` の各カット・各項目のコマの範囲が `render` の計算(`plan_cuts` と表示の区間)と一致すること、同じ台本で `render` の重ね画像が切り替わるコマ(`ovl_XXXX.txt` の区間の境目)と、`/api/state` の項目の `frames` から求めた切り替えのコマが一致すること(ffmpeg の結合テスト)、素材の中のコマの式(止める・ループ)、メディアのスレッド・ffmpeg のワーカーが上限で 503 になった後、終われば次の要求が成功すること、`render` と同じ配置(共通の `scene` を使うこと。切り出し後も `render` の既存のテストが通ること)、ffmpeg・ffprobe の呼び出しに `-protocol_whitelist file` があること、埋め込みの JS に `innerHTML` が無いこと。HTTP のテストは標準ライブラリの `TcpStream` で生の要求を送る。画面の操作は Chrome の自動操作で確認する(台詞に `<script>` などを含む台本で、文字として表示されること)。
- **ロック**: 2つ目のコマンドがロックを取れずに エラー 2 になること。
- **予約名**: 台本のファイル名が追加の予約名(大文字小文字違いを含む)のとき エラー 2 になること。
- 検証コマンド: `cargo fmt --check` / `cargo clippy --workspace --all-targets -- -D warnings` / `cargo test --workspace`。

## 9. 受け入れ条件

- sample の台本で `number` → `build` → `prompts` → 素材を置く → `bubbles` で調整 → `render` と進め、`output.mp4` ができる。
- 動画で、縦書きの吹き出しが台詞に合わせて出入りし、ト書きの枠が次の区切りまで出ていて、動画の素材が最後のコマで止まる(`loop` ではループする)ことを、Human が目で確認する。
- GUI で見た配置と、`render` の結果の同じ時刻のコマが一致する。
- §8 のテスト(ffmpeg の結合テストを飛ばさずに)と検証コマンドがすべて通る。
