# Script2Video 合成音声の取り込み 設計

## 1. 目的

`@cast` にエンジン名を書いた役の台詞を、`build` が音声合成で生成する。
肉声(収録ファイル)と合成音声を同じ台本に混在させる手間を減らすため。
合成した音声は肉声と同じ処理(48kHz 化・無音削除・ラウドネス正規化・配置・重なり指定)に流す。

## 2. ゴール / ノンゴール / アンチゴール

**ゴール**
- エンジン付きの役の台詞が、`build` だけで音声になる。
- 台詞単位で「肉声を使う」に切り替えられる。
- 上書きで音声を失わない(退避する)。

**ノンゴール**
- `number` での合成(ID 採番だけの軽い工程に保つ)。
- 新しいエンジンの追加(VOICEVOX / AivisSpeech / XTTS のみ)。
- 役別トラック・テイクの合成(合成は常に台詞1つ=単独ファイル)。

**アンチゴール**
- 肉声の収録ファイルを、バックアップなしで消すこと。
- 台詞の文面・設定が変わっていないのに、毎回再合成して時間を使うこと。
- エンジン名の無い役の挙動が変わること(今まで通り肉声のみ)。

## 3. 台本仕様の変更(`台本仕様.md` に反映する)

### 3.1 @cast
- エンジン名を書いた役が「合成役」になる。書かない役は今まで通りの「肉声役」。
- 書式は Script2Voice-Rust版 と同じ:
  `役名:話者名:style,エンジン名,language=ja,各種パラメータ...` (エンジン名は `voicevox` / `aivis` / `xtts`)。
  肉声役は従来どおり `役名:話者名,パラメータ...`。
- 音響パラメータ(`pan` `distance` `height` `volume`)と外見描写は合成役にも使う。
- エンジン固有パラメータは Script2Voice-Rust版 §@cast の名称をそのまま使う。
- **`@cast` の有効範囲**: ある `@cast` から次の `@cast` までの台詞が、その定義に従う。同じ役を再度定義したら、それ以降はその定義に置き換わる(合成役→肉声役、声の変更も可)。

### 3.2 @script
- 行内の臨時パラメータ `( )` に `voice=rec` を書くと、その台詞は合成せず、肉声を使う。
  例: `A(voice=rec):今日はいい天気ですね`
  肉声役の台詞に書いても何も起きない(警告も出さない)。
- 合成役の台詞に限り、読み指定 `'単語|読み'` を使える(Script2Voice-Rust版と同じ。区切りは半角 `|` のみ)。
  エンジンへ渡す文は「読み」に置換し、字幕・吹き出しの表示は「単語」にする。
  肉声役では従来どおり廃止(`'` は台詞の一部)。

### 3.3 build での扱い

台詞ごとに次の順で判定する。

| 条件 | 動作 |
|---|---|
| 肉声役、または `voice=rec` | 合成しない。従来どおり `voices/` の収録ファイルを使う |
| 合成役で、テイク(範囲ファイル `S01_L003-L007.wav` 等)が台詞を覆っている | 合成しない。警告する。テイクには触れない |
| 合成役で、`voices/S01_L003.wav` が無い | 合成して作る |
| 合成役で、ファイルがあり、合成記録と一致(文面・設定が同じ) | 再合成しない。そのファイルを使う |
| 合成役で、ファイルがあるが、合成記録と不一致(文面・設定の変更、または肉声など別のファイル) | 既存ファイルを退避し、再合成して置き換える。`Process.log` に記録する |

- 「新しい台本に従う」とは、上の最終行の動作を指す。
- 合成は単独ファイルとして `voices/S01_L003.wav`(モノラル・48kHz)に書く。以降は肉声と同じ経路。
- エンジンが使えない・合成に失敗した台詞は、既存の失敗規則(§3.4: 不足として仮の無音で配置、エラー報告)に従う。

### 3.4 退避(バックアップ)
- 置き換える前の `voices/S01_L003.wav` を `voices/backup/S01_L003.<日時>.wav` に移す(`<日時>` は `YYYYMMDDTHHMMSS`)。台詞IDがファイル名で分かる。
- 退避したファイルは `build` が読まない・消さない。
- `voice=rec` の台詞のファイルは退避も変更もしない。

### 3.5 合成記録
- `voices/synth.json` に、合成した台詞IDごとに「エンジン名・合成に使った文・エンジンのパラメータ・出力ファイルのハッシュ」を記録する。
- ファイルのハッシュが記録と違えば、そのファイルは合成音声ではない(人が差し替えた肉声など)とみなす。
- `work/` は削除してよい領域なので、記録は `voices/` に置く。

## 4. 実装の方針

- 流用元: Script2Voice-Rust版の `s2v-engines`(`PORTING.md` に従い**コピー**。パス依存にしない。独立して進化させる)。流用元のコミットを `PORTING.md` に追記する。
- `s2v-core`: `Cast` に `engine_type`・`style`・`language`・エンジン固有パラメータを追加。パーサーで `@cast` のエンジン書式、複数回の `@cast`(範囲での置き換え)、`voice=rec`、合成役の読み指定を扱う。
- `s2v-cli` の `build`: 収録ファイル照合の前に「合成工程」を挟む。合成が必要な台詞が無ければ、エンジンを起動しない。
- エンジンの接続先・起動方法は `config.toml` に Script2Voice-Rust版と同じ形で追加する。
- 検証(`validate`)で、エンジン名の誤り、未設定のエンジン、`voice=rec` の綴り違いを報告する。

## 5. ビルダーに任せる点

- `@cast` の複数回出現を現在のパーサーがどう扱っているか調べ、必要なら拡張する(台詞の所属する `@cast` を位置で解決する)。
- 合成記録のハッシュ方式、エンジンへ渡すパラメータの詳細。
- テストの組み立て(エンジンはモックで)。

## 6. 設計者の判断(あなたの指定ではない。確認してほしい)

1. 合成は `build` で行い、`number` は触らない。
2. オプション名は `voice=rec`。
3. 退避先は `voices/backup/`、ファイル名は `S01_L003.<日時>.wav`。
4. 合成記録は `voices/synth.json`。
5. テイクが覆う合成役の台詞は、合成せず警告する(テイクは複数台詞を含み、置き換えると壊れるため)。
6. エンジンが使えない台詞は、既存規則どおり「不足」として仮の無音で配置する。
7. `s2v-engines` はコピー(パス依存にしない)。
8. 肉声役の読み指定は引き続き廃止。
