# Script2Video ③ bubbles(吹き出し・ト書きの配置の GUI)設計メモ

正本は `2026-10-14-script2video-video-design.md`(以下「設計書」)の §5。このメモは 2026-10-15 のブレインストーミングで決めたことと、その理由を残す。決定は設計書の §2.1・§5.1・§5.4・§8・§10 に反映済み。

## 目的と成功の条件

- 自動配置の吹き出し・ト書きを、人が画面で動かし、大きさや表示時刻を調整して `bubbles.json` に保存する。`render` はその配置を使う。
- 成功の条件(設計書 §9): sample の台本で `bubbles` で調整 → `render` し、GUI で見た配置と `output.mp4` の同じ時刻のコマが一致する。

## 決めたこと

| 論点 | 決定 | 理由・却下した案 |
|---|---|---|
| 同期のサーバーとメディアのストリーミング | API・画面は1つずつ順に処理し、メディア(`/media/…`)だけ要求ごとに別スレッド(同時 8 本まで、超えたら 503) | ブラウザの動画・音声の長い Range の読み出しが API を止めないため。却下: 206 を 2 MiB に切る(単純だが Human が B を選んだ)、ffmpeg でコマだけ返す(同期が粗い) |
| ffmpeg の検査 | `render` の手順 1 と同じ検査を同じ関数で行う(無い・古い → エラー 2) | `bubbles` でも再生できない素材のコマの取り出しに ffmpeg を使うため。設計書 §5.1 の文言どおり |
| ブラウザで再生できない素材(HEVC・ProRes の `.mov` など) | 画面は `<video>` の読み込みエラーのときだけ `GET /media/frame/<カットID>?n=<コマ番号>` に切り替え、サーバーが ffmpeg でそのコマを PNG にする | 見た目を確実にするため。却下: 「再生できません」の表示だけ、起動時の ffprobe によるコーデックの推定 |
| 計画の分け方 | 2d-1(サーバー)と 2d-2(画面)の2つ | 安全面を先に固めて Codex のレビューを通し、画面はその API の上に載せる。レビューの範囲を絞る |
| 共通部分 | できるだけ共有する(Human 指示)。`s2v-render::scene`(項目の組み立て・大きさと配置の決定(手動・自動・切り詰め)・1項目の描画)と `s2v-cli::prepare`(予約名・リンク・設定・ロック・Process.log・鮮度・フォント・ffmpeg/ffprobe の版・`bubbles.json` の読み込みと拡大縮小・素材の照合と ffprobe の検査)。違いは引数で表す(素材の不足: render はエラー、bubbles は許容) | GUI と出力の配置の一致をコードの構造で保証するため。`scene` を `s2v-cli` に置かないのは、`s2v-bubbles` → `s2v-cli` の依存が循環するため |
| 新しい依存 | `tiny_http` のみ。トークンは既存の `getrandom`(Cargo.lock にある)。ブラウザは `cmd /C start "" <URL>` を引数の配列で起動 | 依存を増やさない |

## 構成(2d-1)

- `s2v-render/src/scene.rs`(新規、`render.rs` から移す): `render` と `s2v-bubbles` が使う。切り出しは振る舞いを変えず、`render` の既存のテストがすべて通ることを条件にする。
- `s2v-cli/src/prepare.rs`(新規、`render.rs` から移す): `render` と `bubbles` の起動時の検査。
- `s2v-bubbles`(新規のライブラリ):
  - `security.rs`: トークン(32 バイト → 16進 64 文字)、クッキー、Host・Origin の検査、Content-Type と本文の大きさ、共通の応答ヘッダー、定数時間の比較。HTTP に依存しない純粋な関数。
  - `range.rs`: Range の解釈(設計書 §5.4 の規則)。純粋な関数。
  - `media.rs`: 起動時に読み取りだけを許す共有モードで開いたハンドルの保持とメディアの応答(Range・`HEAD`・`Content-Type`)。Windows では `seek_read` で要求ごとに独立した位置から読む。
  - `frame.rs`: ffmpeg でコマを PNG にする(ffmpeg のパスは呼び出し側から受ける)。
  - `api.rs`: `state`・`render`・`layout`・`save`・`quit`。
  - `server.rs`: `tiny_http` の受け付けループ(メディアはスレッドへ、それ以外は順に処理)。
  - `assets/`: 埋め込みの HTML/JS/CSS。2d-1 では状態を表示するだけの仮の画面。
- `s2v-cli/src/bubbles.rs`(新規): コマンド。`prepare` → 待ち受けの用意 → URL → ブラウザを開く → 受け付けのループ。ロックは終了まで保持する(順序は設計書 §5.4)。

## API・エラー・安全

要求と応答の型、エラーの応答、安全(守る相手、メディアの固定、ffmpeg の入力の制限、クッキー)、起動と終了の順は、設計書 §5.4 にだけ定義する(このメモでは繰り返さない)。保存の手順と中身は §5.2、画面の時刻(コマ番号)・背景の収め方・重ねる順と原点・ドラッグは §5.3。

## 設計のレビュー(Codex gpt-6.1-sol medium、2026-10-15)への対応

判定「直してから」(Important 12、Minor 3)。すべて設計書に反映した。

| 指摘 | 対応 |
|---|---|
| `/media/frame` の TOCTOU(大きさ・更新時刻では差し替え・上書きを検出できない) | Windows の共有モードで読み取りだけを許して開き、終了まで保持する(Human 承認)。ffmpeg には同じパス。409 は廃止 |
| ffmpeg が素材の外を読みうる | 素材を読む ffmpeg・ffprobe の全呼び出し(`render` を含む)に `-protocol_whitelist file`。守る相手を明記し、素材はユーザー自身の信頼できるファイルとする(Human 承認) |
| メディア 8 本の上限が全体の上限でない | `/media/frame` は同時1つ・10 秒・32 MiB。tiny_http の接続ごとのスレッドの扱いは計画の最初のタスクで挙動を確かめて決める |
| `/api/render` の入力の検証が無い | render・layout・save で同じ検証を画像を作る前に行う |
| 固定名のクッキーが別ポートと衝突 | `s2v_<port>`。別ポートのサービスへの送信は前提(同じユーザーのプログラムからは守れない)に含める(Human 承認) |
| PNG だけでは位置が合わない | `X-S2V-Origin` ヘッダーと `state` の `image:{dx,dy,w,h}` |
| 切り詰めの項目を描けない | `/api/render` は `{id, manual\|null}`。切り詰めはサーバーが共通の `scene` で決める。人が決めた大きさで収まらないときだけ 422 |
| ミリ秒とコマの食い違い | 画面の時刻はコマ番号。カット・項目のコマの範囲と素材の中の時刻はサーバーが `render` と同じ関数で計算。`/media/frame` は `?n=` |
| 背景の収め方が無い | `state` に `fit`・`background`。画面は `canvas` の縦横比 |
| 保存の安全 | リンクの拒否、`create_new` の一時ファイル、各段階の失敗時に残るもの(§5.2) |
| 未知の ID の保存の矛盾 | 既存の未知の ID はサーバーが引き継ぐ。要求の新しい未知の ID は 422。既知の ID が無ければ自動に戻す |
| テストの不足 | 共有モード、並列の Range、打ち切り・上限、保存の失敗注入、`state` のコマの範囲と `render` の一致などを §8 に追加 |
| 起動・終了・ログ(Minor) | 順序を §5.4 に。ログはメディアのスレッドから主スレッドへ知らせて書く |
| API の形の食い違い(Minor) | 型は §5.4 にだけ定義 |
| ドラッグの判定(Minor) | 輪郭は自由に動かし、手を離して 422 なら直前の確定値に戻す(§5.3) |

## テスト(2d-1)

設計書 §8 の bubbles のサーバーの列挙。単体(`security`・`range`・検証・`scene` の切り出し後の `render` の既存のテスト)、HTTP の結合(`s2v-bubbles/tests`。標準ライブラリの `TcpStream` で生の要求)、ffmpeg(コマの取り出し、`S2V_SKIP_FFMPEG_TESTS` の規則は 2b と同じ)、CLI(`--no-open` で起動して URL を読み `/api/quit` で終わる。ロックの競合)。2d-2 の担当: 埋め込みの JS に `innerHTML` が無いこと、Chrome の自動操作。
